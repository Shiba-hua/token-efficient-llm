# 03 中训练：把已有基座变成更适合任务的起点

[返回目录](../README.md) · [上一章：预训练](02-pretraining.md) · [下一章：SFT 与蒸馏](04-sft-distillation.md)

“中训练”没有跨团队统一边界。本地图按实际操作讨论：在基础预训练之后、面向最终行为的后训练之前，继续学习领域、长上下文或推理语料。名称相同不保证训练目标相同；推理轨迹可能被一个团队叫 mid-training，另一个团队放进 SFT。

## 1. 三类能力补课与一个整合问题

| 问题 | 代表路线 | 能改变什么 | 与 token 效率的关系 |
| --- | --- | --- | --- |
| 基座不懂目标领域 | DAPT/TAPT、领域继续训练 | 知识、术语与任务分布适配 | 可能少依赖外部资料/重试，原始研究多数未测 |
| 基座读不懂长文或多文件 | 长序列数据工程、位置/窗口扩展 | 可处理范围与长距离关系 | “能读更多”不等于“应该每次读更多” |
| 基座缺少可用解题模式 | Rho-1 数学继续训练、SmolLM3 reasoning mid-training | 推理知识与行为初始化 | 可能增强长链，也可能让输出更长 |
| 补一项能力损伤另一项 | 数据混合、checkpoint 合并、分阶段复测 | 保持短/长任务与思考模式兼容 | 需要多任务预算曲线，单一峰值分数不够 |

原文阅读范围与实验条件见 [E02、E07、E12–E13](../sources/early-stages.md)。

## 2. DAPT 与 TAPT：相关数据量和匹配程度的竞争

Don’t Stop Pretraining 的 DAPT 在较大领域语料上继续训练，TAPT 在任务训练文本上继续训练，并比较从外部选近邻文本的增强方式。TAPT 更贴近目标但覆盖小；DAPT 更广却可能浪费在与任务无关的领域内容上，二者还能顺序组合。[原论文](https://aclanthology.org/2020.acl-main.740/)

其代表性在于把“继续学一点相关内容”拆成可以比较的策略，并展示错域适配的风险。实验使用 RoBERTa encoder 与分类任务；把它直接讲成现代 reasoning decoder 的短链秘诀，会跨越尚无证据的环节。小团队若想沿此路线做 token 效率，应固定任务性能后测外部检索需求和实际重试是否下降。

## 3. 长上下文训练与压缩研究是互补也竞争的

Data Engineering for Scaling Language Models to 128K Context 研究长序列怎样抽样：在每个数据域内部增加长文本，同时保持域比例，而不是把所有内容换成书籍。LLaMA-2 7B/13B 在有限继续训练后获得长距离检索能力；不同训练量能否外推到更长窗口并不相同。[原文 §3–6](https://arxiv.org/html/2402.10171v1)

它与[07 章的检索/压缩](07-prompt-context.md)解决不同问题。长上下文让模型能读完整材料；检索与压缩决定当前任务只需读哪些材料。扩大窗口可能提高能力上限，却让每轮输入更昂贵。公平比较应给“长上下文直接读”“检索后读”“压缩后读”相同资料权限，并把检索与压缩自身计入成本。

## 4. 推理中训练与双模式：能力增强没有自动的长度方向

Rho-1 在数学语料上继续训练，通过损失选择提高学习效率；它并不教模型统一缩短答案。SmolLM3 则公开了长上下文阶段与 reasoning mid-training，后续再构造 think/no-think 模式。这里“能选择不思考”是控制能力，是否同样可靠还取决于任务。[Rho-1](https://arxiv.org/html/2404.07965v1)、[SmolLM3](https://huggingface.co/blog/smollm3)

SmolLM3 报告 reasoning 阶段使 RULER 长上下文能力退化，并通过与长上下文 checkpoint 合并恢复。这个案例说明阶段之间存在干扰，不能把长上下文、数学能力和少 token 当作自然同向增长。它是一个公开配方中的观察，没有独立证明所有模型都会这样遗忘。

## 5. 原论文结果怎样读

| 实验 | 模型、任务与对照 | 结果和限制 |
| --- | --- | --- |
| DAPT/TAPT | RoBERTa-base、四域八分类任务，比较原始模型与相关/错域继续训练 | ChemProt F1 81.9→84.2；领域匹配重要。没有生成长度 |
| 128K data engineering | LLaMA-2 7B/13B、64K–80K 训练，检索和 BookQA | 部分能力需约 5B 继续训练 token；仍需长序列算力，未测省输入 |
| Rho-1 | 1B/7B、15B 数学语料，对照完整 CLM 损失 | 能力与训练效率证据，部署曲线待测 |
| SmolLM3 | 3B，多阶段训练，think/no-think 与 RULER | 模式分数不同，推理训练影响长上下文；无等性能总 I/O 降幅 |

较稳定的认识是“适配效果与数据和能力组合有关”。尚无相称证据支持“中训练比后训练更适合省 token”或“先长上下文再推理总是最佳顺序”。OpenAI/Anthropic 未公开的阶段命名、数据比例和训练实现列为未知，不按开源配方推断。

## 6. 阅读顺序与下一步问题

先读 DAPT/TAPT 的匹配对照，再读长序列数据工程，最后看 SmolLM3 的多阶段整合；用 Rho-1 把数据选择和中训练连接起来。

| 初步 idea | 最近邻 | 可检验的新差异 |
| --- | --- | --- |
| 继续喂领域文本让模型少查资料 | DAPT/TAPT、Rho-1 | 在新题族上是否减少检索与重试，而非仅记住答案？ |
| 给模型更长窗口就解决 Agent 效率 | 128K 数据工程、长上下文模型 | 和按需检索比，在哪个文档/任务重复率下成本划算？ |
| 合并推理与长上下文 checkpoint | SmolLM3 配方 | 跨任务的 Pareto 改善是否能保留，合并系数能否迁移？ |

本地图的机会判断：优先研究“适配后是否减少反复检索或失败重试”这类可观察链条；大规模从头补长上下文主要服务能力上限，通常不适合作为小团队第一个省 token 实验。
