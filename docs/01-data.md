# 01 数据准备：该保留什么，才可能让模型少走弯路

[返回目录](../README.md) · [上一章：总论](00-overview.md) · [下一章：预训练](02-pretraining.md)

数据路线改变的是模型学到的知识、解法与失败习惯。**训练数据更少、答案更干净、推理更短，是三个不同目标。** 前两者有助于研究可行性，但只有最后落实到相同任务性能下的部署成本，才回答本项目的主问题。

## 1. 从“挑好文本”到“挑有用解法”的路线地图

| 研究问题 | 代表路线与方法 | 通俗机制 | 与其他路线的关系 |
| --- | --- | --- | --- |
| 相同训练预算应该读哪些文档？ | FineWeb/FineWeb-Edu、DCLM | 清理、去重，再用质量或教育价值筛选 | 文档级筛选；不直接规定模型回答多长 |
| 各领域应该占多少比例？ | DoReMi | 用小代理模型找值得增加训练量的数据域 | 与过滤可组合；保留文档不变也能改变混合 |
| 一篇好文档的每个 token 都值得学吗？ | Rho-1 | 全文仍输入，只对更有学习价值的位置施加损失 | 从文档选择细化到损失位置选择 |
| 哪些问题值得生成昂贵轨迹？ | s1 的质量/难度/多样性筛选 | 先挑有信息量的问题，再花教师预算 | 小样本数量不代表低教师成本，也不代表短 CoT |
| 哪条正确轨迹值得学生模仿？ | Shortest-correct self-training、C3oT、TokenSkip | 分别选择短解、改写短解、删除冗余文字 | 同属轨迹构造；在[04 章](04-sft-distillation.md)比较训练机制 |
| 什么能用作奖励或真值？ | 答案规则、执行测试、过程标签、人工审定 | 分别验证终点、程序行为或中间步骤 | 信号能力不同，不能按字段名称宣称“绝对干净” |

这些分支由[数据中心训练综述与原文记录](../sources/early-stages.md)交叉得到。综述按数据操作分类，章节按生命周期分类：例如 TokenSkip 的标签来自输入压缩研究，却用于输出轨迹 SFT，必须同时出现在跨阶段索引中。

## 2. 文档过滤、域混合和 token 选择各自补什么

**FineWeb 与 DCLM 的意义是把数据选择变成受控实验。** FineWeb 分步比较抽取、过滤与去重，再形成教育子集；DCLM 提供统一候选池、训练配方和评测，使筛选方法能在相同预算下比较。两者都支持“数据配方可以显著改变基础能力”，但没有据此测出模型完成一道题会少说多少 token。[FineWeb](https://arxiv.org/html/2406.17557v2)、[DCLM](https://arxiv.org/html/2406.11794v4)

**DoReMi 改变域的训练份额。** 它让小模型暴露各域相对参考模型尚未学好的部分，再据此分配权重，迁移到大模型。它与“删掉低质量文章”既不等价也不冲突：前者决定不同类型内容读多少遍，后者决定候选内容是否保留。难点在于小模型认为有用的数据是否仍适合更大模型。[DoReMi](https://arxiv.org/abs/2305.10429v4)

**Rho-1 将选择细化到 token，但没有从输入里删除 token。** 它保留上下文，只屏蔽部分训练损失，避免一篇文本中的噪声和已充分学会的部分主导更新。因此“损失只保留 60%”不能直接解释为训练前向便宜 40%，更不能解释为部署回答短 40%。[Rho-1 §2](https://arxiv.org/html/2404.07965v1)

## 3. 从解题数据到高效解题数据

s1 按质量、难度和多样性，从约 59K 候选挑出 1K 训练问题；它代表“选有信息量的少数题”，并非“只训练容易的短题”。相反，最短正确自训练先给同一道题采多条解，再选短且通过验证的一条。C3oT 用教师改写；TokenSkip 用重要性分类器删除文字。**选择问题、选择解法、压缩表达**是三个可独立消融的操作。[s1](https://arxiv.org/html/2501.19393)、[自训练](https://arxiv.org/html/2502.20122v3)、[TokenSkip](https://arxiv.org/html/2502.12067v3)

只保留短轨迹可能偏向容易题、熟悉模板或侥幸命中答案。只保留正确答案也不能保证过程正确。数据集需保留题族、难度、采样次数、被拒轨迹及验证方式，才能判断缩短来自学习更好的解法，还是删掉了难样本。相关能力损失反例与可控压缩比较见[04 章](04-sft-distillation.md)。

![数据质量的四个独立维度](../assets/plots/data-four-axes.svg)

保留的概念图用于区分质量维度，不是三个数据集的质量排名。图中的维度须分别审计；一个维度通过不能替代其他维度。

## 4. “干净训练数据”仍有哪些不能跨越的边界

| 数据形态 | 可以低成本检查什么 | 仍不能自动保证什么 |
| --- | --- | --- |
| 数值/选择答案 | 格式、等价化、部分符号验证 | 参考答案本身正确，问题无歧义 |
| 代码加测试 | 给定测试的通过率、可重跑环境 | 测试覆盖完整、没有硬编码或污染 |
| 教师 CoT | 最终答案一致、部分过程检查 | 每一步正确，轨迹忠实反映计算 |
| 工具/GUI 演示 | 已记录动作、某些状态变化 | 动作仍可重放、当前软件上有效 |
| 可生成环境 | 任务与终态断言、不同种子/模板划分 | 断言充分、训练测试机制独立 |

OpenMathReasoning 的 `has_answer_extracted` 是来源较明确的筛选条件，不是数学真值证明。OpenCodeReasoning 的执行过滤消融还会改变数据量与难度覆盖，不能从“过滤后性能下降”推出“错误答案有益”。TextbookReasoning 的教材来源也不能消除抽取和改写错误。第一版的具体反例、官方讨论和可复算样例完整保留在[数据技术专题](technical/01-data.md)及[核查记录](../meta/foundations-sources.md)。

对 AppWorld、SWE-Gym、WebArena、OSWorld 等，训练环境、公开演示和独立测试属于不同资源；可执行判分通常比仅有演示更适合奖励，但判分器仍要抽查。详见[评测章](09-evaluation.md)。

## 5. 原文能支持多强的结论

| 实验 | 条件与结果 | 对本目标的含义 |
| --- | --- | --- |
| FineWeb-Edu | 1.71B 模型、固定训练预算，教育过滤改善若干知识任务；全局去重未统一胜过逐 crawl 去重 | 有独立操作消融；没有部署长度结论 |
| DoReMi | Pile、8B；到基线分数约 200K→75K steps，另有代理成本 | 是训练效率，不能标为推理 token 节省 |
| Rho-1 | TinyLlama/Mistral-7B、15B OpenWebMath，选择损失优于普通 CLM | 支持学习信号选择；仍需测部署曲线 |
| Shortest-correct / TokenSkip | 多个模型的数学实验中，部分配置明显缩短，部分难题性能受损 | 更贴近输出效率；应保留难度分层和失败成本 |

**多方支持的是数据选择会影响能力，不是某一种过滤器普遍最好。** “最短正确路径一定是最佳训练目标”仍没有相称的跨域证据。对于小团队，优先复用已公开数据和验证器，再验证一个具体选择机制，比先重建大规模语料流水线更容易取得可解释的证据。这是本地图的分析判断。

## 6. 阅读顺序与避免重复已有工作

先读 FineWeb/DCLM 理解受控数据实验，再读 DoReMi/Rho-1 区分选择粒度；若目标是部署少 token，转向最短正确自训练→C3oT→TokenSkip→DAST 的难度修正。

| 初步 idea | 先查的最近邻 | 仍值得验证的差异 |
| --- | --- | --- |
| 每题选最短正确答案训练 | Shortest-correct self-training | 在相同教师采样预算下，是否能保留稀有难题解法？ |
| 用模型筛高质量训练文本 | FineWeb-Edu、DCLM、DoReMi | 改进来自质量、域比例还是与测试集更相似？ |
| 只对关键 token 算 loss | Rho-1 | 关键性是可学习性、验证贡献还是部署缩短收益？ |

研究机会应提出可证伪差异，例如：固定题族覆盖与教师预算，比较“最短正确”与“验证过且保留关键状态的短轨迹”，在未见题族上测等性能成本及难题退化。不能只换一个数据集名称就声称新路线。
