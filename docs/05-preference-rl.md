# 05 偏好优化：让模型偏爱什么，比使用哪个优化器更关键

[返回目录](../README.md) · [上一章：SFT 与蒸馏](04-sft-distillation.md) · [下一章：RLVR 与 Agentic-RL](06-rlvr-agentic.md)

偏好路线通过比较候选行为来改变模型。**人类喜欢、AI 喜欢、答案正确、回答更短，是不同监督目标。** RLHF/RLAIF 是反馈来源与训练流程，DPO/SimPO 是优化方式；只有偏好数据和目标确实包含效率取舍，才能把它们称为 token 效率方法。

## 1. 从基础对齐到效率偏好的地图

| 分支 | 代表方法 | 核心问题与机制 | 证据身份 |
| --- | --- | --- | --- |
| 人类反馈对齐 | InstructGPT/RLHF | 用人类比较训练奖励模型，再优化回答 | 广泛使用的基础范式；原目标不是缩短 |
| AI 反馈扩展监督 | Constitutional AI/RLAIF | 用原则指导批评、修订和比较 | 厂商公开训练路线；省人类标签不等于省 token |
| 直接学习比较 | DPO | 用 chosen/rejected 和参考策略直接更新 | 基础优化方法，简化训练流程 |
| 去 reference 与长度归一化 | SimPO | 用平均 token log-prob 和间隔学习偏好 | 训练效率/偏差处理；不是显式长度惩罚 |
| 学习预算与难度偏好 | TALE、DAST | 把预算、正确性、难度放进样本选择和配对 | 直接效率研究，仍依赖任务与难度估计 |
| 在线成本奖励 | 长度感知 RL、预算条件 RL | 在当前策略 rollout 上学习取舍 | 与本章竞争或组合，详见[06 章](06-rlvr-agentic.md) |

[原文卡 P06、P10、P20–P24](../sources/posttraining-map.md)给出具体来源与阅读范围。

## 2. OpenAI 与 Anthropic 公开方案分别说明什么

InstructGPT 以 SFT、人类偏好奖励模型和 PPO 改善指令遵循，展示小模型在人工偏好目标上可超过更大的基础模型。Constitutional AI 用原则指导自我修订与 AI 比较，使监督不完全依赖人工逐条标注。两者作为基础范式必须了解，但其原始实验不是等性能 token 曲线。[InstructGPT](https://arxiv.org/abs/2203.02155v1)、[Constitutional AI](https://arxiv.org/abs/2212.08073v1)

OpenAI 后续公开的 deliberative alignment 进一步教模型在推理中运用规范，再用奖励优化。它甚至可能需要保留必要的规范推理；不能为了缩短把可靠性约束删掉。这里纳入的是企业**已经公开的方法**，不是猜测其当前私有训练配方。[官方方法](https://openai.com/index/deliberative-alignment/)、[企业证据记录](../sources/vendor-practice.md)

## 3. DPO 与 SimPO 为什么不是“自动省 token”

DPO 将偏好目标写成策略与参考策略的对数比，免去显式训练独立奖励模型及部分在线 RL 流程；如果 chosen 是较长、较完整的回答，模型仍可能变长。SimPO 用长度归一化的平均对数概率和目标间隔，并移除 reference；归一化解决的是不同长度序列如何比较，不等于给每个生成 token 收费。[DPO](https://arxiv.org/html/2305.18290v3)、[SimPO](https://arxiv.org/html/2405.14734v3)

AlpacaEval 的 length-controlled win rate 也是控制评审对长度的偏好，以更公平地测质量；它不报告消耗变少。SimPO 一些模型的平均回答反而更长，是“名字里出现长度就说明缩短”的反例。基础算法的采用情况只能说明它是常见载体，不能证明全局效率最优。

## 4. TALE 与 DAST：预算来源不同，学习目标也不同

TALE 通过离线答案验证搜索可行预算，再用提示预测或后训练学习预算。它把“先给一个合适预算”作为关键变量；数据构造时能看到正确答案，线上只能估计，二者不能混为同一能力。[TALE](https://arxiv.org/html/2412.18547v5)

DAST 用每题的采样成功率和正确轨迹长度估计难度，给难题更多容许长度，再构造正确性/效率的偏好对，用 SimPO 学习。它与统一最短偏好竞争：简单题可以压得多，难题需要保留更长探索。**贡献是难度与配对机制，不是重新命名 SimPO。**[DAST §3](https://arxiv.org/html/2503.04472v3)

两者也与[06 章的预算条件 RL](06-rlvr-agentic.md)不同：一个推测题目需要多少，另一个训练模型服从给定上限；可以组合，但组合收益必须另做消融。

## 5. 原文实验与争议

| 方法 | 条件与主要证据 | 不应外推的结论 |
| --- | --- | --- |
| DPO | GPT-2/GPT-J/Pythia；情感、摘要、对话，评测 reward/KL 或偏好胜率 | 训练简单不意味着部署更短 |
| SimPO | Llama/Mistral/Gemma、偏好数据，评估长度控制胜率与通用任务 | 无 reference 和长度归一化不保证少 token |
| TALE-SFT | Llama3.1-8B/GSM8K，77.56%/241.51→78.57%/139.63 | 其他模型配置有性能损失，离线搜索并非免费 |
| DAST | R1-Distill-Qwen-32B/MATH-500，94.4%/3,782→95.8%/2,044 | 7B AIME 长度会略增，不能宣称每个模型/任务均缩短 |
| DAST 的竞争基线 | 相同 32B/AIME24，最短或强长度惩罚配置压得更多，但准确率损失明显 | “最短”与“等性能最低成本”不等价 |

现有独立路线共同说明偏好可以用于控制行为，也暴露过度优化、长度偏差和难度错配。**尚无足够证据认定某个偏好优化器是 token 效率统一最优方案。** 固定数据、reward/配对、模型和预算后比较，才有助于分清机制贡献。

## 6. 阅读顺序与避免重复

先读 InstructGPT/CAI 确认反馈来源，再读 DPO/SimPO 确认优化载体，最后读 TALE/DAST 的效率标签怎样构造。完整 DPO 推导移至[偏好技术专题](technical/05-preference-rl.md)。

| 初步 idea | 最近邻 | 新贡献应回答什么 |
| --- | --- | --- |
| 把较短正确答案当 chosen | 最短偏好、TALE、DAST 基线 | 怎样避免丢失困难题、检索证据和有效自检？ |
| 用 AI 判断哪条轨迹更经济 | RLAIF、DAST | 评审能否区分无用重复与必要验证，是否有可执行依据？ |
| 用无 reference 的方法训练短链 | SimPO | 效果来自优化器还是配对分布，训练预算是否公平？ |

本地图的机会判断：重点研究难度估计失准和分布漂移，比较离线偏好与在线成本反馈能否在相同教师/rollout 预算下保留难题能力。把成本加进偏好本身已经有前作，创新需要落在新的可验证机制上。
