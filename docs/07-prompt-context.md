# 第 7 章：提示与上下文——让模型读到更少、但足够的信息

[返回总览](../README.md) · [上一章：RLVR 与 Agentic-RL](06-rlvr-agentic.md) · [下一章：Harness 与多智能体](08-harness-agents.md)

读完本章，你应能区分四件事：改写指令、检索材料、压缩上下文、复用缓存；能计算一次压缩什么时候回本；能设计一个同时检查信息保留和后续任务成功的比较实验。

本章沿用全书目标：在任务质量可比较的前提下，改善**整个任务的推理输入加输出 token**。所谓上下文，是模型在某次调用时实际收到的指令、问题、历史消息、工具定义和外部材料。它不是磁盘里保存的全部数据，也不等于用户屏幕上看见的聊天记录。

## 7.1 从一个很普通的浪费开始

假设要回答“仓库今天几点关门”。手册有 200 页，其中一句写着关门时间。把 200 页全部给模型，它可能找到答案，但也可能被别的日期、分店和例外条款干扰。只给“18:00”会很短，却丢掉“哪个仓库、哪一天、是否节假日”的适用条件。

这就是上下文工程的基本问题：找到**完成当前任务所需的信息集合**，并用模型能够正确使用的形式表达。真正的比较对象是任务结果，而不是字数排行榜。

![上下文处理流程](../assets/plots/context-pipeline.svg)

*图 7-1：本教程自绘。筛选和压缩改变模型的输入内容；缓存复用改变处理输入的计算过程。原始证据可以保存在模型上下文之外。*

设任务为 $x$，完整材料为 $D$，上下文构建器为 $g_\phi$，其参数 $\phi$ 可以包括检索数量、压缩率和保留窗口。模型收到 $c=g_\phi(x,D)$ 后生成 $y$。设 $Q(y,x)$ 是任务评分，$N_{\rm task}$ 是包括辅助模型在内的推理总 token。一个明确的研究问题是：

$$
\min_\phi\;\mathbb E[N_{\rm task}(\phi)]
\quad\text{满足}\quad
\mathbb E[Q(\phi)]\geq q_0.
$$

这里的期望是在预先确定的任务分布上取平均，$q_0$ 是事先设定的质量要求。这个约束并不保证每个样本都不退步，因此还要检查高风险子集和失败类型。实际实验通常扫描多个 $\phi$，画出质量与 token 的曲线；并不一定直接解这个优化问题。

## 7.2 Prompt 优化首先改变行为

Prompt 优化是改变任务指令及示例，使模型采用更合适的工作方式。它可能减少不必要的推理、重复确认和格式错误，也可能增加指令长度以减少后续重试。

下面是一个教学改写，效果尚需实测：

```text
原提示：请认真阅读材料，详细思考，尽可能全面地回答问题。

候选提示：回答仓库的关门时间，并给出对应条款的位置。
同时核对仓库名称、适用日期、节假日例外。
如果材料不包含这些条件，指出缺失项，不猜测。
输出：时间；适用条件；证据位置。
```

候选提示比“只输出时间”长，但它把成功条件说清楚。若原方案经常漏掉节假日例外，需要用户追问三次，更长的初始提示可能减少任务总 token。反过来，“请简洁回答”也可能只让最终回答变短，隐藏推理或工具调用量仍然不变。

GEPA 提供了一个值得理解的自动优化实例：它读取执行轨迹和自然语言反馈，诊断失败，提出并评估新的提示，并组合不同尝试中的经验。这说明提示可以通过任务反馈进行搜索；论文报告的质量和 rollout 效率比较，不能直接替代你的部署 token 比较。[GEPA 论文](https://arxiv.org/abs/2507.19457v2)

初学者可以先手工完成同一闭环：固定 30 个开发样例，跑基础提示，给错误分类，每次只修改一类规则，再在未用于修改的测试样例上评估。提示版本、模型、采样参数和工具环境都要存档。不要看着测试答案不断修改提示后，再把同一测试集当作泛化证据。

提示搜索还需要两本账。设离线搜索消耗 $N_{\rm opt}$ 个推理 token，新提示每个部署任务节省 $\Delta N>0$，部署 $M$ 次后的净节省为：

$$
N_{\rm saved}=M\Delta N-N_{\rm opt}.
$$

只有当 $M>N_{\rm opt}/\Delta N$ 时，累计 token 才回本。若只是面向当前任务临时搜索提示，搜索就是当前任务成本，不能称为“训练成本”后隐去。这是本教程的会计恒等式，不是 GEPA 的实验结果。

## 7.3 检索决定把哪些材料搬进上下文

检索增强生成常写成 RAG：先从外部资料库找相关片段，再让生成模型利用这些片段。原始 RAG 工作将生成模型与可检索的外部记忆结合，其目的包括改善知识密集任务；RAG 并不天然以减少 token 为目标。[RAG 论文](https://arxiv.org/abs/2005.11401v4)

为了压缩输入，最简单的流程是：

1. 按章节或语义边界切分文档，并保留文档名、段落位置和版本。
2. 根据问题召回候选片段。
3. 去重并排序，补足标题、适用条件或相邻段落。
4. 在输入预算内选择片段，生成带证据位置的回答。

“召回”表示把可能相关的内容找出来；“排序”表示让更有用的内容排在前面。检索数量 $k$ 很小时，输入少但容易漏证据；$k$ 很大时，更容易覆盖证据，也会带入更多干扰。实践中不能只比较 Recall@k，还要检查答案是否正确以及证据是否支持答案。

可以将片段选择写成一个教学近似：

$$
\max_{S\subseteq D}\sum_{d\in S}v(d,x)
\quad\text{满足}\quad\sum_{d\in S}\ell(d)\leq B_{\rm ctx}.
$$

$S$ 是选出的片段，$v(d,x)$ 是对任务 $x$ 的估计价值，$\ell(d)$ 是按目标模型分词器计得的长度，$B_{\rm ctx}$ 是材料预算。这类似背包问题。但真实片段之间会重复、互补或矛盾，价值通常不能简单相加。因此“相关性分数除以长度”只是可检查的启发式，不是最优保证。

如果检索需要模型改写查询、生成多个查询或做生成式重排，这些调用要计入推理账。向量编码器或交叉编码器没有生成文本，也不是零成本：单列其处理长度、计算或延迟。不要把编码器的一次输入与生成式模型的 token 直接混为同一种计算量。

## 7.4 LLMLingua-2：已经选中的材料还可以再压缩

检索主要回答“选哪段”，压缩主要回答“这段怎样更短”。一个有用的区分是：抽取式压缩保留原文的一部分；生成式摘要用新句子重述。前者减少改写带来的风险，后者可以重新组织信息；两者都可能漏掉重要内容。

LLMLingua-2 将提示压缩建模为 token 分类问题，用双向 Transformer 编码器预测哪些内容值得保留，其训练数据通过大模型蒸馏获得。这里“任务无关”是方法设计目标，不表示任何任务都能承受任意压缩率。官方项目包含 LLMLingua 系列多个方法，阅读和运行时应明确选择 LLMLingua-2。[LLMLingua-2 论文](https://arxiv.org/abs/2403.12968v2)、[官方代码](https://github.com/microsoft/LLMLingua)

教学上可以写为：

$$
s_i=f_\theta(w_{1:L})_i,\qquad
\tilde D=(w_i:\operatorname{keep}(s_i,B)=1).
$$

$w_{1:L}$ 是压缩器读到的序列，$s_i$ 是第 $i$ 个单位的保留分数，$B$ 是期望长度预算，$\tilde D$ 是保留后的材料。这里是方法思想的示意式，不是对官方 tokenizer 对齐、词级合并或预算实现的逐行复现。最终必须使用**下游模型分词器**重新计数，因为压缩器的 token 和下游模型的 token 不一定一一对应。

考虑原句：“没有收据时不得退货，但质量问题除外。”随意删掉“没有”“不得”或“除外”，剩下的字仍来自原文，却可能表达相反规则。因此抽取式不等于逻辑等价。数字、单位、否定词、主体、版本和例外条款都应进入有针对性的检查。

一个最小实验应包含：完整上下文、简单截断、检索后原文、简单规则压缩、LLMLingua-2，以及一种摘要方法。固定生成模型与任务验收，扫描保留率。若压缩器缩短了输入，却让模型多搜索两轮，改善可能已经被抵消。

## 7.5 观察遮蔽和摘要为什么要正面比较

Agent 每次使用工具都会得到观察，例如终端日志、网页正文或文件内容。旧观察会随历史在后续请求里反复出现。观察遮蔽只把较旧的观察替换为短占位符，通常保留最近若干轮的完整内容；不应把它与直接删除整段对话混为一谈。

摘要则将旧历史变成一段较短的记忆。它可能保留跨很多轮仍然重要的事实，但需要生成摘要，也可能丢失精确证据或把猜测写成事实。摘要后的 Agent 还可能改变行动路径，甚至花更多轮重新确认已完成的事情。

《The Complexity Trap》在特定 SWE-agent、SWE-bench Verified 和模型配置下发现，简单观察遮蔽在解题率与费用之间有很强的竞争力，LLM 摘要未稳定胜出。这支持把遮蔽设为强基线；该论文主要比较的费用指标，不能直接改写成任意环境中的 token 改善结论。[论文第 3—5 节](https://arxiv.org/html/2508.21433v3)

先看一个固定轨迹的成本推导。假设共有 $T$ 次模型调用，每次固定输入长 $b$，每轮新增模型动作长 $a$、工具观察长 $o$。第 $t$ 次调用重放前 $t-1$ 轮的全部历史，则：

$$
I_t=b+(t-1)(a+o),\qquad
\sum_{t=1}^TI_t=Tb+(a+o)\frac{T(T-1)}2.
$$

这里计算的是**请求输入长度的总和**。二次增长来自重复发送历史，不是在推导 Transformer 的注意力 FLOPs。最后一轮工具结果如果从未再送给模型，就不会凭空成为输入 token。

若只保留最近 $m$ 轮观察，旧观察使用长度 $p$ 的占位符，仍保留全部动作，则：

$$
I_t^{\rm mask}=b+(t-1)a+
\min(t-1,m)o+\max(0,t-1-m)p.
$$

观察部分受到控制，但动作历史仍增长。因此这个策略不保证无限长轨迹的总输入变成线性。

## 7.6 动手：同一轨迹，三种上下文

在仓库根目录执行：

```bash
python3 examples/context_lab.py
python3 examples/context_lab.py --steps 12 --window 3
```

示例只使用 Python 标准库。它把空白分隔单元作为**合成教学单位**，没有调用 LLM、真实 tokenizer 或 LLMLingua-2。固定 8 次调用，每次基础输入 100 单位，动作 20 单位，观察 200 单位。规则摘要每积累 4 轮旧历史时触发一次，读入旧历史和 30 单位摘要指令，输出 35 单位；摘要中人为保留一个已植入的事实。

默认运行结果：

| 方案 | 主模型输入 | 主模型输出 | 摘要输入与输出 | 任务总量 | 最后上下文仍含植入事实 |
|---|---:|---:|---:|---:|---|
| 完整历史 | 6960 | 160 | 0 | 7120 | 是 |
| 最近 2 轮观察 | 3990 | 160 | 0 | 4150 | 否 |
| 每 4 轮规则摘要 | 3580 | 160 | 945 | 4685 | 是 |

这张表没有测量模型成功率。“保留植入事实”只是字符串检查。我们故意让规则摘要知道应保留什么，展示的是记忆保留机制；不能据此声称真实摘要优于遮蔽。下一步的真实实验应在同一环境检查点分别继续运行各策略，让后续成功或失败来判断压缩是否足够。

示例还提供一个四文档词项重合检索：原始材料共 26 教学单位，选择的片段有 6 单位。它没有向量检索、重排或回答模型，只让你看到输入选择如何进入账本。

## 7.7 一次摘要什么时候回本

假设某次摘要把旧历史从 $H$ 缩到 $S$ 个 token，辅助摘要调用本身消耗 $C$ 个输入加输出 token。若新摘要在之后 $K$ 次请求中持续使用，且轨迹、动作和其他输入不变，净节省为：

$$
\Delta N=K(H-S)-C.
$$

因此需要 $K(H-S)>C$。假设 $H=6000$、$S=600$、$C=6800$，则只再用一次时不回本，用两次才有正的 token 节省。这些是任意教学数值。

这个公式需要三个假设：摘要内容没有引发额外重试；未来调用次数不变；没有把同一段历史重复计入多个压缩事件。真实 Agent 可能同时违反这些假设。所以公式适合预估和解释，不足以替代整条轨迹的实测。

## 7.8 缓存账：重复输入没有消失

前缀缓存保存此前输入的中间状态，下次遇到可复用前缀时，跳过相应预填充计算。vLLM 的自动前缀缓存文档明确区分了预填充收益与生成新 token 的解码阶段；它不会自动减少模型要生成的输出长度。[vLLM 官方文档](https://docs.vllm.ai/en/latest/features/automatic_prefix_caching/)

对同一次调用应记录：

$$
I=I_{\rm uncached}+I_{\rm cached},\qquad
N=I+O.
$$

$I$ 是完整输入，$O$ 是输出。如果数据源已经报告完整输入，不能再加一次 cached 字段，否则会重复计数；也不能把 cached 字段从 $N$ 中扣除后仍称它为“总输入输出 token”。

价格可以另写成：

$$
C_{\rm money}=p_uI_{\rm uncached}+p_cI_{\rm cached}+p_oO.
$$

$p_u,p_c,p_o$ 是各类 token 的单位价格。这里暂忽略缓存写入、存储和工具费用；实际供应商有其他收费项目时应另加，不能套用这个简式覆盖全部账单。

示例连续发送两次 1000 单位输入，总输出 100，第二次复用 900 单位。总量仍为 2100；若人为设定未缓存、缓存和输出的价格权重为 1、0.1、3，则加权成本为 1490。这只是数学演示，不是真实报价。

缓存还会影响压缩决策：一个很长但稳定的前缀可能拥有良好缓存命中率；频繁重写摘要会改变前缀。更短输入与更高缓存复用率之间可能存在取舍。应分别报告完整 token、缓存命中、延迟和费用，让读者知道收益来自哪里。

## 7.9 练习与参考答案

1. **计算题：**旧材料长 3000，摘要长 500，摘要调用花 3600。忽略后续行为变化，至少再使用多少次才回本？
2. **错误诊断：**一种方法输入从 10000 降到 4000，输出从 1000 升到 2000，辅助压缩花 3000。它节省了多少？如果后来还多一次 2500 token 的重试呢？
3. **实验设计：**在示例里把仓库代码改成只在第 1 轮出现的“节假日例外”。怎样判断窗口遮蔽是否安全？
4. **证据练习：**给一条摘要中的事实增加原文件和段落位置。设计一次按需恢复原文的调用，并把这次调用也记账。

参考答案：第 1 题需 2 次，因为 $2\times2500>3600$。第 2 题原方案 11000，新方案 9000，先节省 2000；增加重试后变成 11500，反而多 500。第 3 题不能只检查长度，应设计必须依赖该例外才能答对的后续任务，并与完整上下文对照；若规则把例外固定写入摘要，还要增加未预见的关键事实以检测规则偏置。
