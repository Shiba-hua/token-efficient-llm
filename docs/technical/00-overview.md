读完本章，你应能判断一个“更快、更短、更便宜”的方法究竟改善了哪个量，画出公平的预算曲线，并知道数据、训练和智能体系统分别有哪些可介入的位置。

## 1. 先定义任务，再定义效率

对同一道题，只写一个字可能非常省 token，也可能完全没有完成要求。因此本教程把 **token-efficient** 定义为：在固定任务分布、成功标准和计量口径下，以更少的推理 token 达到相同性能，或在相同 token 成本下达到更高性能。

![性能—成本前沿概念图](../../assets/generated/frontier-concept.png)

上图是概念插画。向左看，是保持性能时节省 token；向上看，是保持成本时改善性能。真实模型不一定产生光滑、单调的曲线，必须画出实际观测点，不能用插画代替实验。

设任务 $`q`$ 来自预先固定的分布 $`D`$ ，方法 $`m`$ 包含模型权重、prompt、工具与控制流程。配置 $`b`$ 可以是最大输出长度、采样次数或整项任务预算。一次运行的轨迹为 $`\tau`$ ，任务得分为 $`s(q,\tau)`$ 。二元任务中它为 0 或 1，也可以是明确规定的连续分数。定义：

```math
Q(m,b)=\mathbb E_{q\sim D,\tau\sim m_b(\cdot\mid q)}[s(q,\tau)],\qquad
C(m,b)=\mathbb E_{q,\tau}[c(\tau)].
```

$`b`$ 是控制条件， $`C`$ 是实际消耗。设置 `max_tokens=8192`，不表示每个任务都用了 8192 token。不同方法提前终止的频率不同，因此主图应使用实际成本。

如果方法 A 在一个观测点上满足 $`C_A\le C_B`$ 且 $`Q_A\ge Q_B`$ ，至少一项严格，就称该点 **Pareto 支配** B。若 A 在低预算有优势、高预算却退化，只能报告对应区间的收益，不能说它在全部预算上更优。研究者常用一个加权分数压缩这两个量，但权重改变时排名可能改变。[OckBench](https://arxiv.org/abs/2511.05722) 和 [OptimalThinkingBench](https://arxiv.org/abs/2508.13141) 提供了两种不同折中方式，详见评测章。

## 2. 一项任务应该记哪些 token

本教程的主口径为方法侧全部模型调用。若轨迹 $`\tau`$ 有 $`K(\tau)`$ 次调用，调用 $`k`$ 的输入和输出分别为 $`I_k,O_k`$ ，则：

```math
c(\tau)=\sum_{k=1}^{K(\tau)}(I_k+O_k).
```

输出包含能取得用量信息的思考与最终回答。规划、摘要、路由、子智能体、选择器、重试，以及方法实际调用的教师都计入。某段工具结果被下一次输入读入时，在该次输入中计数；不能既作为工具返回 token 又在输入中重复加一遍。重复读同一段上下文则会在多次调用中产生多份输入成本。

| 账目 | 主 token 账如何处理 | 还应记录什么 |
| --- | --- | --- |
| 提示、历史、工具定义与返回结果 | 按每次实际输入累计 | 上下文长度、截断策略 |
| 思考与答案 | 按实际输出累计 | 有无隐藏思考用量缺失 |
| 缓存命中的输入 | 仍属于输入 token；单独标记命中量 | 计费单价、计算节省 |
| 离线训练教师、prompt 搜索 | 另记开发/训练账 | GPU 时间、调用费、样本数 |
| 只用于评测的 grader、模拟用户 | 另记评测账 | 判分器版本和成本 |
| 部署期间调用的摘要模型、教师或选择器 | 进入主账 | 调用原因、失败与重试 |

例如一次主模型调用用了 2,000 输入和 500 输出，摘要模型用了 1,000 输入和 100 输出，第二次主模型用了 800 输入和 200 输出，总计 **4,600 token**。即使第一轮有 1,500 输入命中缓存，它们也没有从原始 token 账中消失。只报最终回答的 200 token 会漏掉主要开销。

这是本教程为公平比较指定的协议，不声称所有基准已经采用。跨模型分词器时，同一文本对应的 token 数可能不同，应同时报统一参考分词器的文本长度或字节数。潜在状态、字节 patch、扩散步不能伪装成零成本；还需报告内部计算量、调用次数和时间。相关例子见[相邻方向](10-other-directions.md)。

## 3. 不同阶段怎样改变同一张图

可以把部署看成三件事：模型需要知道什么、运行时读什么、怎样组织行动。数据与训练改变能力和行为；上下文方法改变输入；harness 改变工具、分支和停止决策。

![从数据与训练到完整任务评测](../../assets/plots/research-map.svg)

图为本教程自制流程图：训练与上下文的改动共同影响行动，再由完整任务评测检验。

训练数据更好可能提高同预算性能，但更低训练 loss 并不保证更少部署 token。上下文变短会直接降低某次输入，却可能增加后续搜索。多智能体并行可能降低墙钟时间，同时增加总 token。每一条路径都需要回到任务级账目验证。

## 4. 已经有行业共识了吗

这里把“共识”限定为**多个独立公开训练或部署配方采用的共同基础**，不把单篇论文、单个榜单名次当作行业调查。现有一手文献足以确认一些基础范式；它们尚未给出一个在全部任务、模型和预算上最优的 token 配方。下表是证据范围内的研究地图，不是行业投票结果。

| 环节 | 能确认的共同基础 | token 效率仍需比较的典型方法与直觉 |
| --- | --- | --- |
| 数据 | 质量过滤、去重、训练测试隔离是公开配方的常见步骤 | FineWeb-Edu 用教育质量筛选；DCLM 控制训练设置比较筛法；过程数据选择决定模型模仿哪些长度和解法。没有通用最佳混合比例。[数据章](01-data.md) |
| 预训练 | 自回归下一 token 预测是多种开放模型的基础目标 | MTP 同时训练多个未来位置；改变分词会改变序列长度。二者对部署前沿的影响都需实测。[预训练章](02-pretraining.md) |
| 中训练 | 延续语言建模目标适应领域、数据阶段或上下文长度已被多种配方采用 | DAPT/TAPT、长上下文课程、能力混合与模型合并解决不同问题；阶段顺序与遗忘未有统一解。[中训练章](03-midtraining.md) |
| SFT / 蒸馏 | 用示范响应训练条件生成能力是常见起点 | 短而正确的轨迹筛选、难度覆盖、OPD 的学生分布监督；减少教师文字不能自动保证学生更有效率。[SFT 章](04-sft-distillation.md) |
| 偏好优化 | 用成对偏好或奖励约束生成行为是共同思路 | RLHF/RLAIF 区分反馈来源；PPO 与 DPO 是不同优化路线；长度偏差需要单独控制。[偏好章](05-preference-rl.md) |
| RLVR / Agentic-RL | 可执行任务中可用规则或环境结果提供反馈 | GRPO 是被多个推理配方采用的典型算法，但不是唯一共识解；成本奖励、预算条件策略、工具信用分配仍在比较。[RLVR 章](06-rlvr-agentic.md) |
| Prompt / 上下文 | 输入信息组织会影响任务表现 | GEPA 搜索提示；检索按需取证；LLMLingua 压缩；观察遮蔽与摘要各有损失和开销。[上下文章](07-prompt-context.md) |
| Harness / 编排 | 环境、工具、状态与终止规则必须和模型一起描述 | 按需加载工具、程序过滤结果、单代理/多代理路由；不能假定 agent 越多越好。[编排章](08-harness-agents.md) |
| 评测 | 固定数据与判分、报告性能和成本是可比较的基础 | OckScore、AUCOAA、过程效率、任务完成率口径不同，尚不能互相替代。[评测章](09-evaluation.md) |
| 相邻方向 | 生成内容长度、计算量和延迟需要分别测量 | 推测解码、扩散、latent reasoning、量化与 MoE 各自改变不同项。[相邻方向](10-other-directions.md) |

判断共同基础时，可对照 [DeepSeek-R1](https://github.com/deepseek-ai/DeepSeek-R1)、[Tülu 3](https://allenai.org/blog/tulu-3-technical)、[SmolLM3](https://huggingface.co/blog/smollm3) 与 [DCLM](https://arxiv.org/abs/2406.11794) 的实际配方。它们展示多种有效路径，并不是一套共同的 token 最优性证明。各方法的原始文献在对应章节展开。

## 5. 用 GRPO 练习区分直觉和准确表述

GRPO 可以通俗地理解为：对同一道题采样多条轨迹，让相对奖励更高的轨迹更容易出现。但“正确轨迹一律升、错误轨迹一律降”需要条件。如果同组奖励全是 1，组内奖励减去均值后全为 0；全错也一样。若奖励同时包含成本，较长的正确轨迹也可能低于组均值。

还要区分两个常写成 $`\epsilon`$ 的参数：

1. 优势标准化分母中的小常数用于避免零标准差导致除零。
2. PPO/GRPO 比率裁剪中的参数规定替代目标的裁剪阈值，限制部分更新方向继续获得收益；它不保证实际概率比率留在该区间。

它们出现的位置与作用不同，不能用“eps 都是防除零”解释。[第 06 章](06-rlvr-agentic.md) 会逐项推导，并运行全对、全错和混合奖励例子；原始算法见 [DeepSeekMath](https://arxiv.org/abs/2402.03300)。

## 6. 从想法到可证伪实验

先冻结一个具备稳定判分的任务集，在开发集选定预算点与方法，再在独立测试集一次性比较。最小实验不必训练模型：默认策略、明确的简洁提示、观察遮蔽或工具结果过滤，往往已经是需要击败的基线。若它们留下可重复的失败机制，再判断应该改变数据、训练目标还是控制流程。

报告每项任务的成本与得分，保留失败、超时、重试和预算耗尽记录。用成对抽样估计差异，不把大量同模板变体当成同样多的独立证据。不要只在成功样本上算平均成本：一种策略若把困难任务提前放弃，可能得到很漂亮但误导性的成功样本成本。

离线成本也关系到方法是否值得采用。若开发多花 $`F`$ 单位成本，每次部署预期节省 $`\Delta c\gt 0`$ ，在单位相同且任务分布稳定的假设下，收回成本需要约 $`N\ge F/\Delta c`$ 次部署。这个式子解释摊销条件；它不承诺未来分布和模型价格保持不变。

运行 `python3 examples/evaluation_lab.py`，观察完整账目、Pareto 点、OckScore、AUCOAA 及成对 bootstrap。这里的模拟数据只用于检查数学与统计流程。

## 练习

1. A 用 1,000 token 达到 70%，B 用 800 达到 68%。B 是否支配 A？提示：检查两个不等式，不先挑加权分数。
2. 一次工具输出 10,000 个词，程序保留其中 100 个词送给模型。哪部分进入模型输入账？提示：以真正输入的 tokenizer 计数为准，别把词数直接叫 token 数。
3. 一个摘要器使每轮输入减少 20%，但任务轮数从 5 增到 8。它是否一定省 token？提示：比较整项任务的和，并加入摘要器自身调用。
4. 某模型无权提供隐藏思考用量，应怎样报告？提示：标记成本缺失及可观测部分，不能填零后与完整用量模型排名。
