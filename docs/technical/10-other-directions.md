# 第 10 章：相邻方向——更快、更小与更少 token 分别意味着什么

读完本章，你应能判断一篇“高效推理”论文究竟减少了文本长度、模型计算、显存还是等待时间，并能给推测解码、latent reasoning、扩散语言模型、量化和 MoE 选择合适的评估指标。

这些方向非常重要，但它们改变的是系统的不同部位。把所有加速都称为 token-efficient，会使研究问题失去边界。本教程关心任务表现与总推理输入加输出 token 的关系；同时保留计算、时间和内存指标，才能避免更换计量单位带来的假改善。

## 10.1 先分开四种问题

假设一个系统正确解答同一道题：输入 200 token、生成 800 token，其中最终答案只有 20 token。我们可能做四种改动：

| 改动 | 首先改变的对象 | 需要证明的额外结论 |
|---|---|---|
| 让模型用 200 token 完成同样推理 | 生成长度 | 正确率及任务总输入输出确实改善 |
| 用更快的解码器生成原来那 800 token | 解码时间或调度方式 | 端到端确实更快，辅助计算已计入 |
| 用更低精度执行模型 | 权重/激活的数值表示 | 质量仍满足要求，硬件内核确实受益 |
| 把一部分推理移到连续隐藏状态 | 内部推理表示 | 内部步骤与计算没有被计量隐藏 |

这些改动可以组合。先让模型学会少走无效步骤，再使用高效解码和量化，是合理的研究组合。但每项的独立收益与组合收益都需要测量，不能把速度收益直接换算成“省了多少 token”。

对一个实现 $`A`$ ，至少保留一个指标向量：

```math
\mathbf m(A)=(Q,N_{\rm io},F,T_{\rm wall},M_{\rm peak}).
```

$`Q`$ 是任务质量， $`N_{\rm io}`$ 是约定范围内的输入输出总 token， $`F`$ 是计算工作量（能测 FLOPs 时用 FLOPs，否则明确使用什么代理量）， $`T_{\rm wall}`$ 是端到端时间， $`M_{\rm peak}`$ 是峰值内存。改变模型分词器时，再记录统一参考分词器下的文本长度。没有一个标量能不加假设地替代这些量。

## 10.2 推测解码：让大模型一次验证多个候选

自回归生成按顺序计算下一个 token 的分布。推测解码先用便宜的草稿机制提出多个候选，再让目标模型验证。若候选吻合，目标模型一次批量验证可以推进多个位置，从而减少昂贵串行调用的数量。

经典 speculative sampling 使用接受与校正机制，在其数学条件成立时保留目标模型的采样分布。因此它的直接目标是更快得到原本分布下的输出；不是让目标模型少说几句话。[Fast Inference from Transformers via Speculative Decoding](https://arxiv.org/html/2211.17192v2)

只看一个位置，目标分布为 $`p(v)`$ ，草稿分布为 $`q(v)`$ 。先从 $`q`$ 抽取候选 $`v`$ ，以

```math
\alpha(v)=\min\{1,p(v)/q(v)\}
```

接受。这个比值只对实际由 $`q`$ 抽到、因此 $`q(v)\gt 0`$ 的候选使用。拒绝后从归一化残差分布 $`[p(v)-q(v)]_+`$ 采样，其中 $`[z]_+=\max(z,0)`$ 。若拒绝概率为零，就不需要残差分布。

为什么能够校正？候选直接被接受时，分配给 $`v`$ 的概率质量为 $`\min(p(v),q(v))`$ ；残差步骤补上 $`\max(p(v)-q(v),0)`$ 。两者相加恰好是 $`p(v)`$ 。多位置解码还要处理首个拒绝位置和条件前缀，不能直接把每个位置独立接受的代码当作完整实现。

“相同分布”也不意味着两个程序使用相同随机种子必定输出逐字相同，因为它们调用随机数的顺序可以不同。实际实现还涉及数值精度、采样变换和验证内核，应按照实现承诺检查分布保持或贪心一致性。

用一个教学时间模型理解收益。每轮草稿和校验总耗时为 $`t_d+t_v`$ ，平均接受 $`A`$ 个草稿 token，并额外产生一个校正或目标 token，单 token 常规解码耗时为 $`t_1`$ ，则近似速度比为：

```math
S\approx\frac{(\mathbb E[A]+1)t_1}{t_d+t_v}.
```

假设各轮工作量相近，忽略预填充、最后不足一块、同步和排队开销。接受率低、草稿太贵或验证无法高效批处理时，速度比可能低于 1。公式中的 $`+1`$ 对应经典算法每轮额外推进的位置；其他变体需要按实际行为改写。

计量时至少列出最终输出 token、草稿产生 token、接受率、目标验证位置、目标前向次数和总时间。草稿若作为单独可见模型调用，进入全系统推理账；若部署 API 只暴露最终目标输出，就说明内部草稿用量不可见，不能声称测到了所有模型的总工作。被拒绝的草稿也消耗资源。

## 10.3 Latent reasoning：不写成文字，也仍然需要计算

文字推理每一步把隐藏状态映射成词，再把词的 embedding 送回模型。Latent reasoning 尝试让部分中间计算直接在连续表示中进行，不必每一步都产生自然语言。

Coconut 的代表做法是将模型最后的隐藏状态作为连续思维，再直接反馈为后续输入 embedding。这个机制展示了文字之外的推理路径，不应从“少生成文字”推断出“没有执行中间步骤”。[Coconut 论文](https://arxiv.org/abs/2412.06769v4)、[官方代码](https://github.com/facebookresearch/coconut)

一个抽象表达是：

```math
h_{j+1}=f_\theta(h_j,x),\quad j=0,\ldots,K-1;
\qquad y\sim p_\theta(\cdot\mid x,h_K).
```

$`x`$ 是问题， $`h_j`$ 是内部推理状态， $`K`$ 是内部更新次数， $`y`$ 是最终文字。这里只表达“内部状态反复更新再回答”的思路，并不声称复现 Coconut 的具体 Transformer 输入序列。

设文本推理需要 $`L`$ 个中间 token，而 latent 方法用 $`K`$ 次内部更新。若每次更新和一次文本解码的主要计算近似相当，且其他条件相同， $`K\lt L`$ 才提供一种潜在计算节省来源。真实更新可能涉及不同序列长度、缓存方式和额外模块，必须测量，不能凭两个数字直接算加速比。

一个尤其常见的误读是：“原来 500 个推理 token，现在只输出 20 个答案 token，所以省了 96% 计算。”这个结论缺少内部步骤。正确报告可以是：“外显生成文本从 500 降到 20，另有 80 次内部更新；总 FLOPs 与延迟分别为……”。即使结果确实更省，也需要用完整指标说明。

训练成本也需要说明：若使用有文字推理的数据逐步改成 latent 监督，或需要额外训练阶段，训练资源属于另一条账。它不应混入部署 token 曲线，也不应因为部署更短就消失。初学者阅读此类工作时，先找三个接口：内部状态怎样形成、怎样更新、怎样退出并生成答案。

## 10.4 扩散语言模型：少轮数不等于少工作

扩散语言模型可以通过逐步去噪或解除掩码生成序列。LLaDA 使用前向遮蔽过程和反向生成过程，由 Transformer 预测被遮蔽 token，是从头训练扩散语言模型的重要实例。[Large Language Diffusion Models](https://arxiv.org/html/2502.09992v3)、[官方代码](https://github.com/ML-GSAI/LLaDA)

自回归通常先确定第一个 token，再依次确定后续 token。掩码扩散可以先放置一组空位，每轮对许多位置作预测，再根据采样策略确定一部分内容。两种机制最后都可能输出同样长的 128 token 文本。

令输出长度为 $`L`$ ，去噪轮数为 $`S`$ 。一个**每轮完整处理所有输出位置**的简化实现，会访问大约 $`SL`$ 个输出位置；具有有效 KV cache 的普通自回归解码，在生成阶段每步新增一个位置，共新增 $`L`$ 个位置。于是：

```math
V_{\rm diffusion}=SL,\qquad V_{\rm AR,new}=L.
```

$`V`$ 只是教学性的“位置处理次数”，不是 FLOPs。AR 的新增位置仍会读取旧 KV，扩散各位置可以并行，双方预填充、注意力长度和算子形状不同。不能用 $`SL/L=S`$ 断言扩散必然慢 $`S`$ 倍；同样不能用轮数从 128 变成 16 断言扩散快 8 倍。

一个更接近实际测量的表达是：

```math
T_{\rm diffusion}\approx\sum_{s=1}^{S}t_{\rm denoise}(L_s,C_s)
+t_{\rm other}.
```

$`L_s`$ 是第 $`s`$ 轮实际参与处理的长度， $`C_s`$ 表示缓存和条件状态， $`t_{\rm other}`$ 包含采样、数据移动、初始化等。分块生成、缓存、只更新部分位置等实现会改变这些量，必须阅读具体实现。双向上下文中的位置如果被修改，其他位置的隐藏表示也可能受影响；不能直接假定所有旧 KV 都像因果前缀一样永久有效。

如果一个扩散方案用更少的去噪轮数但质量下降，应画质量—时间曲线。如果它生成了更短的解题轨迹且质量相当，才另外报告质量—token 的改善。如果同样的文字长度换了不同 tokenizer，则再增加统一参考文本计量。

对于推理题，后面的答案可能依赖前面刚得到的中间结果；对于格式固定、局部可并行的填充任务，依赖结构可能不同。这给出了按任务依赖结构做分层评测的动机，是实验设计推断，不是“扩散一定适合或不适合某任务”的结论。

## 10.5 量化：降低表示精度，不改变 token 的定义

量化将权重或激活从较高精度表示映射到更低比特的表示。AWQ 是以激活信息辅助低比特权重量化的代表方法，研究的是模型压缩及相应执行效率。[AWQ 论文](https://arxiv.org/abs/2306.00978)

对一个均匀量化教学模型，可以写为：

```math
\hat w=s\cdot\mathrm{clip}\left(\mathrm{round}(w/s),q_{\min},q_{\max}\right).
```

$`w`$ 是原权重， $`s\gt 0`$ 是缩放系数， $`q_{\min},q_{\max}`$ 是整数表示范围， $`\hat w`$ 是恢复到实数域后的近似值。这个式子是基本量化直觉，不是 AWQ 完整算法。量化引入的误差是否影响模型能力，要用任务评测回答。

如果模型有 $`P`$ 个权重、每权重 $`b`$ 比特，忽略缩放因子、零点、填充等开销，权重内存约为：

```math
M_{\rm weights}=Pb/8\quad\text{字节}.
```

十亿参数从 16 bit 改为 4 bit，理想权重存储从 20 亿字节降到 5 亿字节。峰值显存还包括 KV cache、激活和工作区，因此“权重缩小四倍”不等于“总显存缩小四倍”，更不等于“token 数缩小四倍”。

低比特是否更快取决于硬件指令、内核、解量化开销、批大小和内存带宽。若原程序没有利用低比特计算，只是临时解包回高精度执行，理论存储优势不能保证同样的速度优势。若量化使错误率变高，Agent 多重试两次，任务总 token 甚至可能上升。

因此量化比较应固定任务、提示和停止条件，报告模型精度、权重格式、执行后端、硬件、并发、质量、生成长度、端到端时间和显存。需要解释的是“单位 token 更便宜了多少，以及任务行为有没有变”。

## 10.6 MoE：每个 token 只激活部分专家

Mixture of Experts 将某些网络层划分为多个专家，路由器为每个 token 选择一部分专家计算。这里的“路由”发生在模型内部；第 8 章的路由是在多个完整模型之间选择，二者层级不同。

Mixtral 是一个具体实例：其稀疏专家层为每个 token 选择两个前馈专家。论文区分总参数与推理时激活参数，说明模型容量与单 token 激活工作可以分离。[Mixtral of Experts](https://arxiv.org/abs/2401.04088)

用一个简化专家层表达：

```math
h'=\sum_{j\in\mathrm{TopK}(r(h))}\pi_j(h)f_j(h).
```

$`h`$ 是 token 的隐藏状态， $`r`$ 给专家打分， $`\mathrm{TopK}`$ 选出 $`k`$ 个专家， $`\pi_j`$ 是组合权重， $`f_j`$ 是第 $`j`$ 个专家网络。这里 $`k`$ 是专家数，不是一次生成的 token 数。

若共享参数量为 $`P_s`$ ，每个专家参数量为 $`P_e`$ ，共 $`E`$ 个专家，每 token 激活 $`k`$ 个，则粗略有：

```math
P_{\rm total}\approx P_s+EP_e,\qquad
P_{\rm active}\approx P_s+kP_e.
```

这个参数量近似有助于理解结构，不能精确推导 FLOPs 或总显存。路由、负载不均、跨设备通信和共享注意力都消耗资源；专家权重还需要存储或调入。相比总参数相当的稠密模型，稀疏激活可能更省计算；相比一个小得多的稠密模型，则必须测量质量和系统代价。

MoE 没有从定义上减少输入或输出 token。如果更强的 MoE 模型用更短轨迹完成任务，这是模型能力及行为的实测结果，不能只凭稀疏结构预先断言。

## 10.7 动手：三个计量错觉

运行第 8 章的脚本，并查看末尾 `resources` 字段：

```bash
python3 examples/agent_budget_lab.py
```

脚本使用纯 Python 精确枚举一个三项分布。目标分布为 $`(0.1,0.6,0.3)`$ ，草稿分布为 $`(0.5,0.3,0.2)`$ ，直接接受的概率质量为 $`(0.1,0.3,0.2)`$ ，总接受率为 0.6。加上归一化残差步骤贡献后，恢复出的分布恰好为 $`(0.1,0.6,0.3)`$ 。

这是单位置校正的算术验证，没有执行大模型或测量加速。它说明“保留采样分布”的含义，并提醒你不要把一个便宜草稿直接当作目标模型结果。

接着看两个合成资源计数：

| 项目 | 输出 | 正确解释 |
|---|---:|---|
| 输出长度 | 128 | 最终文字位置数 |
| AR 生成阶段新增位置 | 128 | 忽略预填充，每步新增一个位置 |
| 全序列扩散，16 轮 | 2048 次位置访问 | $`16\times128`$ ，不是 2048 个最终输出 token |
| 十亿权重、16 bit | 2,000,000,000 字节 | 理想权重数据大小 |
| 十亿权重、4 bit | 500,000,000 字节 | 未包括量化元数据、KV 和工作区 |

这些结果足以揭示单位混淆，但不足以决定哪个真实模型更好。下一步必须使用真实硬件计时，并确保同样的质量要求和测量边界。

## 10.8 用一张比较表约束研究结论

在阅读论文或自己的实验时，可以填写以下空表。不要在没有观测时用理论预期填入“改善”。

| 方法 | 任务质量 | 完整输入/输出 | 内部额外工作 | 端到端时间 | 峰值内存 |
|---|---|---|---|---|---|
| 原始基线 | 实测 | 实测 | 明确基线 | 实测 | 实测 |
| 推测解码 | 实测或满足的分布保证 | 最终与草稿分开 | 草稿与目标验证 | 实测 | 实测 |
| Latent reasoning | 实测 | 外显文本单列 | 内部更新次数、计算 | 实测 | 实测 |
| 扩散语言模型 | 实测 | 最终文字单列 | 去噪次数、处理长度 | 实测 | 实测 |
| 量化 | 实测 | 实测 | 精度、解量化、内核 | 实测 | 实测 |
| MoE | 实测 | 实测 | 激活专家、通信 | 实测 | 实测 |

所有时间实验还应说明冷启动或热启动、预填充是否计入、批大小、并发、缓存、输入长度与输出长度。如果用户关心整个 Agent 任务，就要把工具等待、路由、失败恢复和最终整合也放进端到端时间。

## 10.9 练习与参考答案

1. 一种推测解码使 1000 token 输出从 20 秒降到 12 秒，草稿另外生成 1400 token。可以分别声称什么？
2. 一个 latent 方案把 400 个文本推理 token 换成 100 次内部更新。仅凭这些数字，能否得出四倍加速？
3. 扩散方案输出 256 token，执行 32 轮完整序列处理。位置访问是多少？为什么不等于输出 token？
4. 一层有 1 亿共享参数、8 个各 2 亿参数的专家，每次激活 2 个。总参数和激活参数各约多少？为什么不能只按激活参数安排显存？

参考答案：第 1 题在所测配置下端到端速度比为 $`20/12\approx1.67`$ ；最终输出长度没减少，草稿工作另报，不能称总 token 减少。第 2 题不能，还需要每次更新的计算、缓存、预填充和质量。第 3 题为 $`256\times32=8192`$ ，相同输出位置被反复处理。第 4 题总参数约 17 亿，激活约 5 亿，但未激活专家仍须存储或按需调入，还存在 KV 与工作区。
