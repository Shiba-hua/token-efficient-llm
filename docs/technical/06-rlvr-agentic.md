## 1. RLVR：把判断标准接到执行结果上

Reinforcement Learning with Verifiable Rewards（RLVR）利用可以自动检查的任务结果提供奖励。例如代码是否通过测试、数学答案是否与有效参考答案一致、文件是否被正确修改。这里的“可验证”描述反馈来源，不指定必须用 PPO、GRPO 或其他算法。

一个最简单的奖励是 $`r(x,y)=\mathbf1[\mathrm{verify}(x,y)]`$ 。 $`x`$ 是任务， $`y`$ 是生成结果，指示函数在检查通过时为 1，否则为 0。看上去很客观，但 verifier 仍可能错：答案解析器漏掉等价表达，单测覆盖不足，环境检查只看到了“文件存在”却没有检查内容。训练会针对实际运行的检查器优化，不会针对我们心里的完整需求优化。[Tülu 3 的 RLVR 配方](https://arxiv.org/abs/2411.15124)

代码解通过几个测试不等于程序对所有输入正确；最终数学答案正确也不等于自然语言推导每步正确。因此要区分结果奖励、过程监督和推理内容真实性。RLVR 不要求事先有一条教师 CoT，但要求题目与验证条件可靠，且当前策略有机会获得有区别的反馈。

## 2. GRPO：同一道题多做几次，再比较

想象一位学生对同一题写了四份解答。与其再训练一个模型预测“这道题通常能得几分”，GRPO 可以直接用这四份的平均奖励作基线。对任务 $`x`$ ，从 rollout 策略采样 $`G`$ 个回答 $`y_1,\ldots,y_G`$ ，取得奖励 $`r_1,\ldots,r_G`$ 。

本教程使用总体标准差，定义

```math
\bar r=\frac1G\sum_{i=1}^{G}r_i,\qquad
s_r=\sqrt{\frac1G\sum_{i=1}^{G}(r_i-\bar r)^2},\qquad
\hat A_i=\frac{r_i-\bar r}{s_r+\epsilon_{\mathrm{std}}}.
```

$`\epsilon_{\mathrm{std}}\gt 0`$ 是数值保护。不同框架可能使用样本标准差、移除标准差归一化或改变 batch 聚合方式，因此复现时还要记录具体实现。DeepSeekMath 提出的 outcome-supervision GRPO 将同一回答的组相对奖励用于该回答各 token，并省去了 PPO 中额外训练的价值模型。[DeepSeekMath §4.1](https://arxiv.org/html/2402.03300v3#S4.SS1)

对纯二值奖励 `[1,1,0,0]`，均值为 0.5、标准差为 0.5，优势约为 `[1,1,-1,-1]`。但这不意味着“正确就天然是正优势”。优势比较的是**最终奖励与组均值**：奖励还包含成本或其他项时，正确回答也可能低于平均值；一组全都正确时，也可能有长短之分。

必须记住两个特殊情况：

- 若只有二值正确性奖励，全部正确 `[1,1,1,1]` 或全部错误 `[0,0,0,0]` 都得到零优势。
- 更一般地，只要组内最终奖励全相同，中心化后就全为零。零优势不等于整个训练系统零更新，因为另加的 KL、辅助损失或优化器状态仍可能产生更新。

若全部样本失败，盲目把组大小从 8 加到 64 可能只是更昂贵地确认能力下限。可以先检查题目可解性、提示、采样截断和模型能力，再考虑调整课程或引入 SFT。反之，全部成功的简单题在二值奖励下缺少组内改进信号；是否加入效率目标，应由部署需求决定。

## 3. 两种 epsilon，解决两个完全不同的问题

GRPO 常沿用上一章 PPO 的裁剪结构。对回答 $`i`$ 的第 $`t`$ 个模型 token：

```math
\rho_{i,t}=\frac{\pi_\theta(y_{i,t}|x,y_{i,\lt t})}{\pi_{\mathrm{old}}(y_{i,t}|x,y_{i,\lt t})},
```

```math
J_{\mathrm{task}}=\frac1G\sum_i\frac1{T_i}\sum_t
\min\!\left(\rho_{i,t}\hat A_i,
\mathrm{clip}(\rho_{i,t},1-\epsilon_{\mathrm{clip}},1+\epsilon_{\mathrm{clip}})\hat A_i\right).
```

上式展示原始风格的按回答平均，再按回答长度平均；后续方法也有其他归一化方式。另加参考策略 KL 正则时，可写作 $`J=J_{\mathrm{task}}-\beta J_{\mathrm{KL}}`$ ，需要说明 KL 的采样估计、权重和分布，不能只报“有 KL”。

| 参数 | 出现位置 | 作用 | 不承担的工作 |
|---|---|---|---|
| $`\epsilon_{\mathrm{std}}`$ | 奖励标准差分母 | 防止除零，缓和极小分母 | 不限制概率比 |
| $`\epsilon_{\mathrm{clip}}`$ | $`[1-\epsilon,1+\epsilon]`$ 区间 | 限制裁剪目标对某些方向的更新激励 | 不处理零标准差，也不硬锁概率比 |

二者恰好常被写作同一个希腊字母，但不可互换。把分母保护设成 0.2 与把裁剪设成 $`10^{-8}`$ ，都不是“差不多的防抖参数”。本教程代码特意使用两个不同变量名，避免在调参时混淆。

## 4. 想省 token，先防止奖励鼓励失败

最直观的设计是 $`r=\mathbf1[\mathrm{correct}]-\lambda C`$ ，其中 $`C`$ 是任务成本。但若正确答案花 100 个单位、 $`\lambda=0.02`$ ，奖励为 −1；立即交一个错误答案只花 1 个单位，奖励为 −0.02。优化器选择后者并不是“学坏了”，而是忠实地执行了目标。

一个更容易理解的教学设计是有界、正确性门控的成本项：

```math
r_i=c_i\left[1-\lambda\min\left(\frac{C_i}{B},1\right)\right],
\quad c_i\in\{0,1\},\quad B\gt 0,\quad0\le\lambda\lt 1.
```

$`B`$ 是成本标尺， $`C_i\ge0`$ 是该 episode 的完整部署 token 成本。错误奖励为 0，正确奖励在 $`[1-\lambda,1]`$ 中，所以任何正确回答的奖励都高于任何错误回答。这个性质来自有界惩罚和 $`\lambda\lt 1`$ ，不是因为名字叫“门控”。

![四个回答全部正确时，二值奖励优势全零；加入门控成本后，较短回答优势为正，较长回答优势为负。](../../assets/plots/posttraining-grpo.svg)

图 6-1：四个合成正确回答，成本分别为 10、40、70、100。蓝线只有正确性信号，红线还比较成本；它说明“全正确得到零优势”只适用于同奖励条件。图展示公式行为，不能作为模型训练有效的证据。

门控仍有局限：成本达到 $`B`$ 后惩罚饱和；全部失败时没有成本区别；高奖励不等于任何一条正确轨迹都有正优势。更重要的是，逐条正确奖励高于错误奖励，并不保证策略的成功率优先。取 $`\lambda=0.2`$ ，策略A总是成功且成本为 $`B`$ ，期望奖励为0.8；策略B成功率0.9、成功时成本为 $`0.1B`$ ，期望奖励为 $`0.9\times0.98=0.882`$ 。即使精确优化这个目标，也可能选择成功率更低的B；这不只来自采样噪声。更根本的目标可以写成约束问题：最大化质量，满足 $`\mathbb E C\le B`$ ；或最小化成本，满足 $`Q\ge Q_{\min}`$ 。用标量奖励只是优化取舍的一种方式，最终必须画出多预算下的性能—成本 frontier。

长推理、工具验证和重试有时是成功的必要条件。成本最好按任务或难度分层观察，而不是让简单题的短轨迹成为所有问题的统一模板。训练采样出的多条候选与教师打分是离线成本；若部署时也采样多条再投票，所有候选都必须计入部署横轴。

## 5. Agentic-RL：从一段回答到一个环境过程

智能体不是只生成答案，还会改变环境。令 $`h_t`$ 表示到第 $`t`$ 步可见的历史， $`a_t`$ 是模型产生的动作， $`o_{t+1}`$ 是环境返回的观察。一次 episode 是

```math
\tau=(h_0,a_0,o_1,a_1,\ldots,o_T),
\qquad
G_t=\sum_{k=t}^{T-1}\gamma^{k-t}r_k.
```

$`G_t`$ 是从该步起的折扣回报， $`0\le\gamma\le1`$ 。Agent 往往只能看到部分环境状态，所以用历史或记忆形成输入。折扣让远期奖励影响变小，但它不是对 token 成本的精确替代：一次工具动作可能比另一动作多花几十倍输入 token。

下面为简化讨论明确取 $`\gamma=1`$ ，令 $`J`$ 为完整 episode 的期望总回报；用 $`\hat A_t`$ 估计该步回报减去不依赖当前动作的基线。一个常见策略梯度估计写作

```math
\nabla_\theta J\approx
\mathbb E_\tau\sum_t\hat A_t\nabla_\theta\log\pi_\theta(a_t|h_t).
```

这是理解信用分配的入口：任务最后成功，哪些早期动作值得增加概率？若只在终点给一个奖励，可以用回报或组相对信号传播到先前动作，方法简单但方差可能大；价值模型、中间验证、分段任务奖励则提供不同粒度的信息，也引入更多误判来源。密集奖励并非天然更好，可能把策略引向“容易刷分的局部步骤”。

以搜索任务为例，模型产生检索词，搜索工具返回段落，模型再决定继续检索还是回答。Search-R1 提供了将推理和搜索交替纳入 RL 的公开实例。[官方代码与论文入口](https://github.com/PeterGriffinJin/Search-R1) 这里应在模型生成的推理和工具调用 token 上计算策略 logprob；环境返回的段落是条件输入，不是模型选择的动作，通常要从策略 loss 中 mask 掉。但这些段落随后占用的输入 token 仍算部署成本：**不参与梯度的内容也可能产生费用**。

## 6. 终止、验证和环境版本也是学习问题

“停止”是动作。过早停止可能失败，成功后不停搜索则浪费。只要出现结束标记就发成功奖励，会让策略学会立刻结束；只要调用检查工具就发奖励，会让它反复检查。奖励应依赖真实完成条件，区别于模型声称自己完成。

对于改文件、调用工具的任务，初始状态、可用权限、工具响应和终态检查应形成一致的实验条件。AppWorld 是一个例子：用任务专属测试检查数据库变化及目标达成。[AppWorld 官方评测说明](https://github.com/StonyBrookNLP/appworld#-evaluating-the-agent) 但“可执行环境”不代表其中的测试题可直接拿来训练后继续报告同题泛化；训练任务、开发任务和测试任务仍要隔离。

失败也要分类：模型做错、环境启动失败、网络故障、超时与输出截断，训练含义不同。若基础设施坏了却发零奖励，策略可能被迫避开某类本来可用的工具。特别是长轨迹，观察压缩、工具版本和最大轮数会改变学生访问的状态；训练 harness 与部署 harness 不一致，可能抵消算法收益。

信用分配最终要回到可解释的日志：哪个动作出现、当时看到什么、验证器为何判定、组奖励均值与方差是多少。只有 reward 曲线，无法区分有效学习与检查器漏洞。

## 7. CPU 小实验与练习

```bash
python3 examples/posttraining_lab.py --section grpo --self-test
```

也可以在仓库根目录执行下面的 Python 片段：

```python
from examples.posttraining_lab import group_advantages, gated_reward

print(group_advantages([1, 1, 0, 0]))
print(group_advantages([1, 1, 1, 1]))
rewards = [gated_reward(True, cost) for cost in [10, 40, 70, 100]]
print(rewards)
print(group_advantages(rewards))
```

第一行约为 `[1,1,-1,-1]`，第二行全零。最后一组都正确，但长回答得到负优势。程序没有 rollout 引擎，也没有把这个奖励宣称为推荐的生产训练配方；它用于核对定义和反例。

练习一：用 `[0,0,0,1]` 手算优势，解释唯一成功样本与三个失败样本的权重。练习二：将门控公式中的 $`\lambda`$ 设为 1.2，找出正确不再严格高于错误的反例；代码会拒绝这个参数，是为了守住示例所声明的条件。练习三：画出一次“搜索—阅读—总结—失败重试”的调用图，把每次模型的输入、输出 token 加入成本；说明把工具观察从策略 loss 中排除后，哪些费用仍存在。

你现在已经见到三种不同监督：SFT 模仿示范，偏好优化学习比较，可验证 RL 学习执行反馈。它们可以组合，也可以互相补足；是否改善 token 效率，要由相同测试条件下的部署曲线回答。下一章转向不改模型参数的 Prompt 与上下文工程。
