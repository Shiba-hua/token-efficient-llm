## 1. 论文要解决什么问题

这篇论文把“推理模型被诱导把生成预算耗在无关任务上”定义为一个运行时安全问题。攻击者把文字插入用户上下文、检索文档、工具输出或其他外部字符串，要求模型先解一个诱饵，再回答用户问题。模型可能一直解 Sudoku 或逐字符解码，耗尽输出预算而没有有用答案（denial of service, DoS），或者仍然回答但付出远高于正常请求的推理成本（denial of wallet, DoW）。输入内容本身可以看起来无害，因此 Llama Guard 一类内容安全分类器没有合适的违规类别可触发。

作者强调，危险信号不只是“输出很长”：合法代码、数学和摘要任务也可能长。攻击轨迹的几何特征是诱饵接管后，新的推理块既越来越不像用户问题，又反复落在模型此前已经走过的语义区域。RecurGuard 因而在生成中监测“任务偏离 + 自身复现”的合取条件，并在条件持续成立时提前取消生成。

威胁模型是黑盒提示注入。攻击者能控制进入上下文的文字、选择诱饵，并在自适应测试中知道检测器的一般设计；不能改权重/解码参数、读隐藏激活或 logits、改 system prompt、绕过监测器或取得梯度。论文不主张解决 jailbreak、恶意内容、投毒、后门或成员推断。

## 2. 攻击、指标和可见性边界

OverThink 将与用户问题无关的 Sudoku 约束问题拼进上下文，并要求“先解决它”；ExtendAttack 则把用户问题转成混合进制 ASCII 等编码，要求模型逐字符解码后再回答。二者都把推理拖长，但前者是无关约束求解，后者是与原问题有结构联系的顺序解码。

论文还构造四种自适应变体：C1 Topical CSP 用用户问题领域词汇包装约束诱饵；C2 High-entropy filler 将填充分散到多主题；C3 Structured-diverse filler 改变每步结构以降低重复；C4 Task-aligned filler 让填充始终与任务语义对齐。C2、C3 只做 N=3 smoke test，放大倍率均不超过 1.5×，所以没有扩大样本；C1、C4 在主模型上各 N=100。

输出 token 放大定义为

```math
\alpha = \frac{\mathbb{E}[T_{attack}]}{\mathbb{E}[T_{clean}]} .
```

其中 $`T`$ 是输出 token 数，论文没有把它等同于总 FLOPs 或总端到端延迟。liveness failure 定义为答案 token 少于 5，或攻击输出达到生成上限 $`T_{max}`$：

```math
LF(Y)=\mathbf{1}[\text{answer tokens}<5\ \lor\ T_{attack}\ge T_{max}] .
```

因此 O1 是约 1× 的正常结果，O2 是仍回答但 $`α>1`$ 的 slowdown，O3 是没有可用答案的 liveness failure；DoW 包含 O2/O3，DoS 对应 O3。

防御者有四种可见性：A 完整原始推理（RecurGuard 可用）；B API 提供摘要后的 thinking（可用但敏感度下降）；C thinking block 为空/隐藏（RecurGuard 结构上不可用）；D 只给最终输出（只能 QDM）。[FIG:fig1] 图 1 把攻击进入文本上下文、RecurGuard 在线观察 trace、触发 HALT、否则交给 QDM 的路径画在一起；表 1 则给出四种 regime 的可见性矩阵。它说明“推理是否暴露”是机制成立的前置条件，而不是一个事后校准细节。

## 3. RecurGuard 方法

### 3.1 分块和表示

令暴露的推理词序列为 $`R=(w_1,\ldots,w_n)`$，用户查询为 $`Q`$。以 $`k=64`$ 个词划分非重叠块：

```math
c_t=(w_{(t-1)k+1},\ldots,w_{tk}),\quad k=64.
```

每个块和查询都由 SentenceTransformers 的 `all-MiniLM-L6-v2` 编成 384 维、单位归一化向量 $`e_t=f(c_t)`$、$`q=f(Q)`$，相似度为余弦内积。滑动历史窗口宽度 $`W=20`$ 块。前几块没有足够历史时采用非报警约定，并要求 $`t\ge c_{min}=3`$ 才允许报警。

### 3.2 三个流式信号

1. **Recurrence Rate（RR，复现率）**。在窗口 $`W_t`$ 中，统计和当前块相似度超过 $`τ_r=0.70`$ 的历史块比例：

```math
RR_t=\frac{1}{|W_t|}\sum_{i\in W_t}\mathbf{1}[\operatorname{sim}(e_t,e_i)>0.70].
```

它检测当前块是否反复回到同一个语义区域；多样化的正常推理通常使 RR 较低。

2. **Volume Growth（VG，体积增长）**。先定义 embedding 集合的平均两两欧氏距离（MPD）：

```math
MPD(S)=\frac{2}{|S|(|S|-1)}\sum_{i<j}\|e_i-e_j\|_2,
```

再计算加入当前块后的变化：

```math
VG_t=MPD(W_t\cup\{t\})-MPD(W_t).
```

正 VG 表示语义云扩张、产生新内容；接近 0 或为负表示不再覆盖新的语义区域。$`|S|<2`$ 时 MPD 置 0，早期值采用不报警约定。

3. **Task-conditioned Progress（TP，任务条件进展）**。令当前块与查询的相似度为 $`a_t=\operatorname{sim}(e_t,q)`$，与所有历史块的最高相似度为 $`r_t=\max_{i<t}\operatorname{sim}(e_t,e_i)`$，则

```math
TP_t=a_t-r_t.
```

TP>0 表示当前块更靠近查询而不是既有推理，是有任务进展的迹象；显著负值表示它远离查询、却与过去推理相似，是“复现坍缩”。这也是三个信号中最能区分正常长任务与攻击的信号：单看 RR 会把正常重复分析误报，单看 VG 会把暂时不扩展的合法推理误报，TP 补上了“是否偏离用户任务”的条件。

### 3.3 连续报警与停止

固定阈值为 $`τ_R=0.20`$、$`τ_V=0.01`$、$`τ_P=-0.738`$、$`c_{min}=3`$。单块报警为：

```math
A_t=\mathbf{1}[RR_t>\tau_R\ \land\ VG_t<\tau_V\ \land\ TP_t<\tau_P\ \land\ t\ge c_{min}].
```

只有 $`A_t=1`$ 连续 $`S=3`$ 块才宣布攻击；任何一个正常块都把计数器归零。在线伪代码的核心是：取下一个 64 词块，编码并算 RR/VG/TP；若三条件同时满足则 `alarm_count += 1`，否则清零；计数达到 3 就返回 ATTACK 并在触发块取消生成。该规则把“一个偶然异常块”与持续自循环分开。

论文的解释性定理不是普适安全证明。若 $`r_t-a_t\ge m>0`$，则 $`TP_t\le -m`$；当 $`m>|\tau_P|`$ 时 TP 条件必然触发。另一个推论是，要避开 TP 报警，攻击者必须满足 $`a_t\ge r_t+\tau_P`$：可以降低复现，或提高与查询的对齐。后一条形成了后面的放大-规避权衡。

### 3.4 QDM 后备监测器

没有 reasoning trace 时，QDM 将最终输出按 80 词切块，计算各块对查询的余弦相似度均值：

```math
QDM(Y,Q)=\frac{1}{M}\sum_{m=1}^{M}\operatorname{sim}(f(y_m),f(Q)).
```

当 QDM<0.318 时标记；空输出得分置 0，短于 80 词的残余作为一块。QDM 不看历史复现、必须等完整输出产生，因此不能提前停止，也不是 RecurGuard 那种只用良性数据校准的主检测器：其阈值用 50 条 SQuAD clean calibration 输出及匹配的 OverThink 开发输出选择，测试行保持分离。对于摘要任务，QDM 的短查询锚点会把正确摘要误判为漂移，实验中 CNN/DailyMail 的 clean FPR 达 89%。

RecurGuard 阈值则只用良性混合开发集：SQuAD 0–49 共 50 条，加 HumanEval、GSM8K、CNN/DailyMail 各 30 条；网格搜索选取在完整混合集上 FPR=0 的最敏感设置，并锁定后测试。

## 4. 实验条件和分母

开放权重实验在 NVIDIA A100、HuggingFace Transformers/SentenceTransformers 上进行。模型是主模型 DS-R1-Qwen-7B（DeepSeek-R1-Distill-Qwen-7B，完整主评估）、DS-R1-Llama-8B、Qwen3-8B，以及无扩展推理的 Llama-3.1-8B-Instruct（用于说明适用边界）。闭源部分是 Anthropic Sonnet 4.5（摘要 thinking）和 Opus 4.7（所有运行返回空 thinking）。

主数据是固定 seed=42 打乱的 SQuAD validation split：校准 0–49，独立 benign FPR 50–199（N=150），OverThink 200–299（N=100），ExtendAttack 205–254（N=50），自适应扩展 255–354（C1/C4 各 N=100；与 OverThink 行 255–299 在问题索引上重叠，但攻击提示不同）。HumanEval、GSM8K、CNN/DailyMail 各 clean N=100，其中各 30 条参与校准、完整 100 条用于同一 workload 的 FPR 表；因此这些行不是独立于校准的统计证书。TriviaQA clean/attacked 各 25 只在 supplementary artifact 报告，不能替代正文主表。

比较防御包括 B1 99% clean token percentile、B2 zlib 压缩比 proxy、B3 少于 5 个答案 token、B4 相对 clean 均值 z-score>3、QDM 和 RecurGuard。B2 是可重复性的 proxy，不是真正的 perplexity，因为没有 logits。

## 5. 正文主实验结果

### 5.1 攻击放大和 liveness

表 6 的 clean 平均输出 token / OverThink 平均 token / OverThink 放大 / OverThink LF / ExtendAttack 放大 / ExtendAttack LF 如下：DS-R1-Qwen-7B 为 357 / 8,155 / 22.8× / 98% / 22.5× / 92%；DS-R1-Llama-8B 为 344 / 8,016 / 23.3× / 86% / 22.7× / 80%；Qwen3-8B 为 337 / 8,192 / 24.3× / 100% / 19.6× / 44%；Llama-3.1-8B-Instruct 为 14 / 5,701 / 402× / 100% / 212× / 100%。最后一个 402× 是分母伪象：clean 模型只生成 14 token，几乎没有扩展推理，不能解释成攻击对该模型更强。

### 5.2 主攻击检测

在 DS-R1-Qwen-7B 上，OverThink N=100：B1/B2/B4 TPR 均 100%，B3 98%，QDM 100%，RecurGuard 99%（Wilson 95% CI [94.6,99.8]）。ExtendAttack N=50：B1 100%、B2 96%、B3 92%、B4 100%、QDM 96%、RecurGuard 92%（[81.2,96.8]）。RecurGuard 与 QDM 在 OverThink 的 100 条中有 99 条一致，McNemar $`χ^2=0.0,p=1.0`$，没有显著 TPR 差异；RecurGuard 的主要价值在误报和可提前停止，而不是在这两种极端长攻击上击败 QDM。

### 5.3 困难正常题和误报

表 7 的完整 clean profile（表中 SQuAD N=200 含 50 条校准样本）显示：

| clean 任务 | B1 | B2 | B3 | B4 | QDM | RecurGuard |
|---|---:|---:|---:|---:|---:|---:|
| SQuAD QA N=200 | 1% | 1% | 0.5% | 1% | 0.5% | 0% |
| HumanEval code N=100 | 69% | 27% | 17% | 80% | 1% | 1% |
| GSM8K math N=100 | 0% | 0% | 0% | 0% | 0% | 0% |
| CNN/DailyMail summary N=100 | 0% | 2% | 0% | 1% | 89% | 0% |

独立 SQuAD 证书是 indices 50–199 的 0/150 RecurGuard FPR，Wilson 95% 上界 <2.5%；其余长任务同时提供开发样本，所以只能称 clean-workload profile。HumanEval 说明长度阈值会把合法长代码当攻击；CNN/DailyMail 说明只看“输出是否像短查询”会误杀摘要。RecurGuard 在摘要中允许内容远离短指令，只要各新块持续引入新文章内容而非复读，自身复现不会连续成立。

### 5.4 基线比较和信号消融

C1 Topical CSP 仍有 11.9× 放大：B1 TPR 94%、B2 3%、B3 31%、B4 99%、QDM 38%、RecurGuard 21%。C4 Task-aligned filler 为 2.2×：B1 3%、B2 1%、B3 1%、B4 10%、QDM 0%、RecurGuard 0%。这说明长度基线能抓高放大 C1，却无法作为混合 workload 的单独防线（HumanEval FPR 69%/80%）；压缩比遇到语义多样化失效；答案缺失只抓 O3。

表 8 的 OverThink N=100 消融为：RR-only TPR 100%/FPR 4.7%；VG-only 100%/5.3%；TP-only 99%/0%；RR+VG 100%/4.0%；RR+TP 99%/0%；VG+TP 99%/0%；Full 99%/0%。因此 TP 是主要精度信号：RR/VG 可检测重复或不扩展，却不知道它是否偏离查询；加入 TP 的每个配置都达到 0% FPR（在这个评测中）。[FIG:fig2] 图 2 左图是三个信号随 chunk index 进入连续 S=3 触发区的示意，右图把放大倍率与 RG+QDM joint miss 画成自适应边界；不能把左图当所有样本的均值轨迹。

### 5.5 闭源 API

Sonnet 4.5（Regime B，攻击 N=30、clean N=30）所有攻击都回答但放大 21.3×（O2）；QDM TPR 100%（Wilson [88.6,100]），RecurGuard 16.7%（[7.3,33.6]），原因是 provider 摘要 thinking 破坏了原始 chunk-level recurrence。Opus 4.7（Regime C，攻击 N=3 smoke）thinking 全为空，放大 676×；QDM 3/3=100%，RecurGuard N/A。Opus 只有定性 smoke，不作统计推广。

## 6. 自适应边界和部署含义

C1 是论文最重要的残余反例：把诱饵词汇拉回问题主题后，$`a_t`$ 上升，TP 坍缩不再连续；RecurGuard TPR 21%、QDM 38%，两者约 50% 的 joint miss 仍对应 11.9× 放大。长度基线反而能抓住多数 C1（B1 94%、B4 99%），因为主题对齐没有减少输出长度。这是“部分规避”中间态，不受只针对全程 TP 规避的定理 2 约束。

C4 则在 100/100 样本同时绕过 RecurGuard 和 QDM（各 0% TPR），但放大从 OverThink 的 22.8× 降到 2.2×，约下降 90%。按照 $`TP_t\ge\tau_P`$ 的必要条件，攻击者必须不断保持任务对齐或降低复现；在作者给出的构造中，这使模型趋向真正回答而不再无限循环。2.2× 仍是成本开销，故不是“无害”，但风险从严重 DoW 变为低放大 slowdown。C2/C3 的 N=3、≤1.5× 只能作为负控制，不能作为攻击检测率结论。

部署上，Llama Guard 3-1B-INT4 对 OverThink N=50 攻击 0/50（TPR 0%，95% CI [0,7.1]），clean N=50 全通过（FPR 0%），说明输入内容安全不等于计算后果安全。DS-R1-Qwen-7B 被检测后在约 8,155 token 的完整攻击生成前停止，作者报告每个检测攻击约节省 92% 输出 token；这只适用于有非空 reasoning trace 且客户端能取消请求的环境，不能套到 Opus 4.7。以 Opus 4.7 2026 年 5 月价格估算，攻击均值约 $`0.402/请求、clean 约 `$0.00234，约 172× 总 API 成本放大（10,000 次/天约 $`4,000 对 `$23）；676× 是输出 token 放大，不能混成同一个指标。

## 7. 与推理时 token 效率的关系

这项工作测量的是输出 token 数、liveness、检测率/误报率和早停节省，不是训练成本、FLOPs、GPU latency 或完整质量-成本前沿。它把 token 效率问题补成安全约束：一个“有效但很长”的推理与一个被诱饵困住的“长且自循环”轨迹，不能用同一个长度上限处理。对在线推理而言，chunk 级持续停止可以把已经产生的少量监测计算换成大部分剩余 token 的节省；对隐藏思维 API，QDM 只能在成本已经发生后标记，不能声称提升实时 token 效率。

## 8. 局限、可迁移性与问题

第一，RecurGuard 需要非空原始 trace；摘要 trace 已显著降低敏感度，隐藏 trace 使它结构上不可用。第二，自适应 C1/C4 只在 DS-R1-Qwen-7B 上各 N=100，不能推广到所有模型；模型间只对主攻击做有限交叉验证。第三，C1 仍未解决，作者提出在 RAG 中用源文档等更任务感知的锚点替代短用户查询。第四，论文没有测试针对 encoder/决策规则的梯度白盒自适应攻击。第五，B2 不是 logits perplexity，只是 zlib proxy。第六，closed API 样本小，Opus N=3 仅 smoke；SQuAD adaptive 与攻击区间共享问题索引，虽提示不同且未用 OverThink 结果设计 C1/C4，仍应避免把它当完全独立样本。

对研究推理 token 效率最值得追问的是：源文档锚点能否在不伤害摘要任务的情况下压低 C1 joint miss；隐藏思维 API 是否能提供足够可靠的摘要轨迹；以及在可获得 logits 时，熵/不确定性是否能补足 embedding 复现检测。论文把这些列为后续测试方向，并没有给出结果。
