## 1. 要解决的具体问题

检索增强语言模型（RALM）通常把检索到的多个文档直接拼到用户输入前面。这样可以给冻结的 LM 提供外部知识，但会同时带来三个问题：输入 token 变长、模型未必能在长上下文中找到中间位置的信息、无关文档会干扰甚至降低答案质量（§1）。RECOMP（Retrieve–Compress–Prepend）在检索和 LM 之间插入一个压缩器：它读入查询/前文 $`\mathbf{x}`$ 和检索文档集合 $`D=[d_1,\ldots,d_N]`$，输出短文本摘要 $`\mathbf{s}`$，最后把 $`[\mathbf{s};\mathbf{x}]`$ 交给冻结 LM $`M`$。

作者为输出设定三个要求（§2）：

1. **Concise**：尽可能短；如果检索无关、或者 LM 本来就不需要检索，允许 $`\mathbf{s}=\emptyset`$。
2. **Effective**：把摘要前置后，LM 应能生成目标 $`\mathbf{y}`$。
3. **Faithful**：摘要应能被 $`D`$ 蕴含，并且可解释。

训练时作者主要直接优化前两个要求；faithfulness 没有显式损失，而是在第 6 节人工抽样检查。因此，“摘要短且有助于当前 LM”是训练目标，“事实忠实”是后验审计目标。这一取舍是全文理解 token 效率的关键：压缩器不是为人类阅读摘要而训练，而是为下游 LM 的任务效用而训练。

![An illustration of RECOMP, which compresses retrieved documents into a textual summary before prepending it as input to a language model at inference time.](../../../../assets/papers-v3/2310.04408/figure-1-recomp-pipeline.png)

**读图（Figure 1）**：输入问题“when did they stop making the Nissan Xterra?”，检索文档包含大量汽车历史文本。直接把约 749 tokens 的 RALM 输入给 LM 会得到错误年份；RECOMP 先把约 58 tokens 的检索证据压成一句摘要，再与问题拼接，LM 得到正确的 2015。图中压缩发生在 LM 之前，因此节省的是 LM 编码检索文档的上下文长度；论文没有把压缩器本身的延迟、FLOPs 或 token 成本纳入一条端到端成本曲线。

## 2. 两种压缩器

### 2.1 抽取式：用下游 LM 的 log-likelihood 选择句子

把 $`D`$ 切成候选句子 $`S_i=\{s_j\}_{j=1}^{n}`$。抽取式压缩器是一个 110M 参数的双编码器 $`\mathrm{enc}_\theta`$（从 Contriever 初始化）：分别编码查询 $`x`$ 和句子 $`s_j`$，取各自 `[CLS]` 表示，内积作为相关性分数。

部署时按

```math
\mathrm{sim}_\theta(x,s_j)=\langle \mathrm{enc}_\theta(x),\mathrm{enc}_\theta(s_j)\rangle
```

排序，再拼接 top-$`k`$ 个句子作为摘要。它只复制原文片段，所以通常比生成式摘要更容易保持可追溯性；作者也明确承认抽取并不保证绝对 faithful。

真正有别于普通检索 reranker 的地方是**正负样本由下游 LM 评价**。定义

```math
\mathrm{Score}(M,y,[s;x])=\log p_M(y\mid[s;x]).
```

对每个训练样本 $`i`$，先用冻结的基座 LM $`M`$ 在所有候选句中找效用最高的

```math
p_i=\arg\max_{s_j\in S_i}\mathrm{Score}(M,y_i,[s_j;x_i]).
```

再从 Contriever 排名较高、但下游分数比 $`p_i`$ 低至少阈值 $`\epsilon`$ 的句子中取最多 5 个负例 $`N_i`$。双编码器以对比损失训练：

```math
\mathcal{L}_i=-\log\frac{\exp(\mathrm{sim}(x_i,p_i))}{\exp(\mathrm{sim}(x_i,p_i))+\sum_{n_j\in N_i}\exp(\mathrm{sim}(x_i,n_j))}.
```

语言建模任务的 $`M`$ 是 GPT-2；QA 任务的 $`M`$ 是 Flan-UL2。QA 中的 Score 改成“前置该句后是否能生成正确答案”的任务分数。训练数据分别从 Wikitext-103、NQ、TriviaQA、HotpotQA 训练集构造，每个查询保留 top-5 文档中的 top-20 句子，并给每个句子加 Wikipedia 页面标题以便脱离原上下文阅读（§3.1）。

一个可跟踪的选择例子：若五个候选句中，句 $`s_2`$ 使 GPT-2 对下一个文本片段的 log-likelihood 最大，则 $`s_2`$ 为正样本；$`s_1,s_4,s_5`$ 虽然经 Contriever 排名靠前，但若其 LM 分数低于 $`s_2-\epsilon`$，便成为负例。压缩器学习的是“哪个句子最能让这个 LM 完成任务”，而非“哪个句子与问题词面最相似”。

### 2.2 抽象式：教师生成候选，任务 LM 负责筛选

抽象式压缩器是 775M 的 T5-large encoder–decoder。它输入 $`[x;d_1;\ldots;d_N]`$，生成可综合多文档信息的摘要。由于没有人工摘要标签，作者用 GPT-3.5-turbo 作为教师生成伪标签，再用下游 LM 做 critic 过滤（§3.2）。

对每个训练样本，作者用多个提示词生成候选摘要：

```math
s_j=\mathrm{Decode}(M_t,[p_j;x_i;D_i]),\qquad
v_j=\mathrm{Score}(M,y_i,[s_j;x_i]).
```

选择 $`v_j`$ 最大的 $`s_t`$。关键的选择性增强规则是再计算无检索输入的分数

```math
v_d=\mathrm{Score}(M,y_i,[x_i]).
```

若 $`v_t<v_d`$，训练目标改成空串 $`\emptyset`$；否则把 $`(x_i,D_i,s_t)`$ 加入蒸馏数据。语言建模中“变差”表现为 perplexity 上升；QA 中作者直接过滤掉摘要没有带来性能提升的例子。于是空摘要不是生成失败，而是一个有监督的“不要把检索证据交给 LM”的动作。

语言建模用四个手工提示词（Table 8）：生成下一句/下两句、选择最可能出现在下一句的句子、或概括文档信息；每个样本四个摘要中只保留让 GPT-2 perplexity 最低者。QA 的 NQ/TQA 要求两句回答摘要，HotpotQA 要求生成 reasoning chain。实际训练时语言建模只抽 Wikitext 训练集 2%（48,013 个样本、每个四次 API 生成）；QA 使用全部 NQ/TQA，HotpotQA 仅处理 gold answer 出现在检索文档中的 56% 训练样本以节约 API 成本。T5 学习这些被任务 critic 过滤过的教师摘要，而不学习教师的 token-level 概率分布。

训练细节（Appendix A.2）：抽取式 batch 64、学习率 $`2\times10^{-5}`$、1000 warmup、3 epochs；抽象式 batch 16、学习率 $`10^{-5}`$、1000 warmup、3 epochs。作者以验证集 reranked perplexity（LM）或准确率（QA）选模型。

## 3. 什么时候返回空摘要

抽象式模型的空摘要来自明确的逐样本比较：摘要前置后的 end-task 分数不超过无检索分数，就以空串作为目标。其动机有两类：检索文档与查询不相关，或查询虽有文档但 LM 已能凭 $`x`$ 完成任务；此时加入文档只有干扰成本。论文没有给出一个固定推理阈值或单独的“是否检索”分类器，空串决策被蒸馏进 encoder–decoder 的生成行为中。

训练统计显示这个动作不是边角情况：抽象式数据的空样本比例为 NQ 25%、TriviaQA 16%、HotpotQA 4%、Wikitext 24%（Appendix Table 5）。测试时 Wikitext 的摘要只出现在 33% 的样本上；第 6 节报告所有抽象式训练集的空摘要比例范围为 4–24%。输入文档长度变化不大，但摘要长度变化显著（Figure 4 及 Appendix Figure 8），说明模型在做自适应增强。抽取式实验固定句子数（Wikitext/NQ/TQA 一句，HotpotQA 两句），没有测试抽取式的自适应空摘要，这是作者明确留下的后续方向。

## 4. 实验设计：到底测了什么成本

作者把任务效果和“提供给 LM 的 evidence token 数”作为主要指标。LM 任务报告 perplexity；QA 报 Exact Match（EM）和答案字符串 token-level F1。token 计数是前置到基座 LM 上下文的检索证据，不包括 QA 的五个 few-shot 示例（这些示例平均 NQ/TQA/HotpotQA 为 110/147/149 tokens）。论文没有报告抽压器推理延迟、抽压器自身输入 token、FLOPs、美元/API 成本，也没有把压缩器和 LM 的总 wall-clock 延迟相加。因此“compression ratio”在文中主要是证据 token 比例，不是端到端计算成本比例。

### 4.1 语言建模（Table 1）

数据为 Wikitext-103；BM25 从 2018-12-20 Wikipedia 语料检索，文档截成不重叠的 100-word 块，每 32 tokens 检索一次，并移除包含当前输入的文章防止污染。测试三个冻结 LM：GPT-2 117M（训练压缩器所用）、GPT2-XL 1.5B、GPT-J 6B（跨模型转移）。基线包括无检索、top-1/top-5 整文档、BoW、命名实体（NE）、BM25/Contriever 句子选择、T5/GPT-3.5 生成摘要，以及利用测试标签的抽取/抽象 oracle。

主要数字如下（表中 # tokens 是证据 token，PPL 越低越好）：

- 无检索：GPT-2 37.84、GPT2-XL 19.89、GPT-J 11.44。
- top-1 原文：141 tokens，PPL 32.90/17.86/10.57；top-5 原文在 GPT-2 上 512 tokens、PPL 35.53，反而比 top-1 差，说明多检索文档不是越多越好。
- 抽取式 oracle 只用约 31–32 tokens，PPL 30.36/16.58/9.92；这是用真实测试 LM 选择句子的上界，不是可部署模型。
- 训练抽取式（Contriever 初始化）约 31 tokens，PPL 33.67/18.19/10.73，三种 LM 均优于 BM25（36.63/19.02/11.08）和 Contriever（35.54/18.98/11.05）。相对 top-1 文档，它把证据压到约 25% token，性能只小幅下降。
- 训练抽象式（T5 初始化）约 15 tokens，PPL 33.64/18.09/10.66；它在表中同时达到最低 token 数和训练模型之外的最好整体效果。T5 原模型只有 15 tokens 但在 GPT-2 上 PPL 37.80，几乎没有利用检索信息；GPT-3.5 为约 33 tokens、PPL 34.84/18.70/10.96。

作者的解释是：BoW/NE 的不流畅字符串会破坏 LM；top-5 整文档会加入无关上下文；学习到的摘要通过任务信号同时选择有效信息和是否为空。这里的“6–13%”是 oracle 对整文档的证据 token 比例，“25%”是训练抽取式相对 top-1 文档的比例，不能混为同一个成本定义。

### 4.2 开放域 QA（Table 2）

基座是 Flan-UL2 20B；检索器是 MS MARCO 上训练的 Contriever，语料同样是 2018-12-20 Wikipedia、100-word 文档。数据/划分：NQ dev、TriviaQA test、HotpotQA dev 随机 500 例。输入含五个随机 few-shot QA 示例，再接检索文档和问题；五文档按检索得分升序放置，最高分文档离问题最近。每个数据集单独训练一个抽取式和抽象式压缩器；抽取式选 NQ/TQA 一句、HotpotQA 两句。

完整 top-5 原文的证据 token/EM/F1 是 NQ 660/39.39/48.28、TQA 677/62.37/70.09、HotpotQA 684/32.80/43.90；无检索则分别为 0/21.99/29.38、0/49.33/54.85、0/17.80/26.10。

- **抽取式训练模型**：NQ 37 tokens、EM/F1 36.57/44.22；TQA 38、58.99/65.26；HotpotQA 75、30.40/40.14。它明显低于完整 top-5 的证据长度，但保留了主要收益。
- **抽象式训练模型**：NQ 36 tokens、37.04/45.47；TQA 32、58.68/66.34；HotpotQA 64、28.20/37.91。NQ/TQA 都约为完整证据的 5%，相对完整 top-5 分别少 2.35 和 3.69 EM 点；HotpotQA 约 11% token，抽取式比抽象式更好。
- **极限与基线**：抽取式 oracle 在 NQ/TQA/HotpotQA 只需 34/32/70 tokens，却达到 60.22/79.29/41.80 EM；这是逐例查看答案指标的上界。T5 原模型用 7–10 tokens，EM 25.90/55.18/23.20，说明极端短并不代表有效。GPT-3.5 摘要约 56/41/107 tokens，EM 37.12/62.03/31.60。

QA 与语言建模的差异很重要：语言建模中 top-1 已经可能优于 top-5；QA 中 top-5 对三套数据都显著优于 top-1，因此压缩的价值在于“保留多文档信息、删掉干扰”。HotpotQA 需要多跳综合，抽象摘要较易遗漏跨文档链条或产生幻觉；这也是作者认为抽取式更稳的原因。

论文附录还把训练于 Flan-UL2 的压缩器转移到 LLaMA-13B。作者报告：QA 转移一般比原训练 LM 差，常无法超过普通 Contriever，且距 LLaMA 自身 oracle 有明显差距；但 NQ/TQA 仍能约 5% token、相对完整文档少于 5 EM 点。这表明文本摘要可跨 LM 使用，但任务 critic 学到的偏好并非完全模型无关。

## 5. 分析、案例与失败模式

### 5.1 “更多证据”不等于“更会用证据”

NQ dev 的 Figure/Table 3 统计了证据中 gold answer 的出现率，以及 LM 复制证据片段的比例。top-5 的 gold-in-evidence 为 57%，高于 top-1 的 36%，但 EM 只是 39.3；当 gold 不在证据时，top-5 仍有 81% 的预测从证据复制，容易把无关片段当答案。训练抽象式压缩器把“gold 不在证据时的错误复制”降到 39%，同时 EM 为 37.0。

附录 Table 9 给出一个直观例子：问题是“host of the late show who was once a correspondent for the Daily Show”，金答案 Stephen Colbert。无检索预测 Chelsea Handler；五篇原文混合了 Conan O’Brien、David Letterman、Jon Stewart 等许多干扰信息，模型仍可能找错；T5(RECOMP) 摘要直接保留“Stephen Colbert 曾是 Daily Show correspondent、2015 年成为 CBS Late Show 主持人”，Flan-UL2 得到正确答案。这个例子支持“让 LM 先看到任务相关的短证据”，但不是所有样本的因果证明。

### 5.2 忠实性与完整性

作者从测试集随机抽取每个数据集 30 个非空抽象摘要，人工标注：faithfulness（能否由检索文档蕴含）、comprehensiveness（是否含足够信息回答问题）、useful（同时满足前两者）。结果（Table 4）如下：

| 数据集 | 模型 | Faithful=Yes | Comprehensive=Yes | Useful |
|---|---|---:|---:|---:|
| NQ | GPT-3.5 | 90% | 97% | 83% |
| NQ | Ours | 80% | 100% | 80% |
| TriviaQA | GPT-3.5 | 97% | 90% | 83% |
| TriviaQA | Ours | 83% | 96% | 77% |
| HotpotQA | GPT-3.5 | 74% | 78% | 50% |
| HotpotQA | Ours | 67% | 74% | 40% |

小模型在 NQ/TQA 上摘要更“够答题”，但比 GPT-3.5 更不忠实；两者在 HotpotQA 都显著变差。样本只有每项 30 个且是作者人工评估，适合作为风险证据而非精确总体估计。论文伦理声明也承认商业 LM 生成训练数据可能含事实错误。

## 6. 与 token 效率推理的关系

这篇工作的贡献不是提出一个新的 tokenizer 或减少生成轨迹，而是把“检索证据 token”变成一个可由下游任务效用控制的中间预算。可迁移的设计模式是：先产生候选信息，再用冻结目标 LM 的真实任务分数选择/过滤；当证据的边际收益为负时，动作应是空输入，而不是强行生成一个看似有信息的摘要。对于推理时 token 预算，这相当于在上下文入口处做一次“有条件的信息写入”：保留足以改变 LM 决策的最小文本，避免把无关检索 token 和错误摘要一起送入后续计算。

但论文实际只测了证据 token 数和任务指标。它没有测量压缩器的输入编码成本、生成成本、端到端延迟、峰值显存、API 成本，也没有把“检索→压缩→LM”与“检索→LM”放在相同硬件上计时。因此不能从 5% 证据 token 直接推出 95% 的总计算节省；压缩器本身仍需编码 top-5 文档，抽象式还可能调用一次 GPT-3.5 生成训练数据（部署时则由 T5-large 生成）。此外，训练目标依赖某个基座 LM：GPT-2 上学到的句子偏好能转移到 GPT2-XL/GPT-J，但 QA 转移到 LLaMA-13B 明显变差。

## 7. 有定位的局限与待验证问题

1. **任务效用优先于显式事实约束**（§2、§3.2、§6）：抽象式训练不带 faithfulness loss，依赖教师摘要和 LM critic；HotpotQA 的 faithful/useful 仅 67%/40%。需要在相同 token 预算下加入可验证引用、句级 entailment 或多跳覆盖约束。
2. **空摘要只在抽象式中真正自适应**（§6，Appendix Table 5）：抽取式固定句子数，没有比较可学习的句数/空输出策略。当前“选择性增强”的强证据主要来自抽象式。
3. **oracle 与实际模型差距很大**（Table 1–2）：oracle 使用目标测试 LM 直接看答案指标挑选句子，不能视为可部署效果；它说明上限存在，不能作为独立复现或因果证明。
4. **跨模型、跨任务稳健性有限**（§6、Appendix Table 10）：语言建模转移较好，但 QA 转移到 LLaMA-13B 后常不能击败普通 Contriever；任务 critic 可能把模型特定偏好编码进压缩器。
5. **摘要忠实性审计规模小，成本指标不完整**（§6）：每数据集每模型仅 30 个非空摘要，且未报告抽压器延迟/FLOPs/显存/总 wall-clock。证据 token 的下降不能单独替代端到端成本曲线。
6. **检索器不是研究变量**（脚注 2、§4）：作者假定已经给出文档集合，未研究检索召回错误如何传递到摘要，也没有把检索失败与压缩失败分开计数。
